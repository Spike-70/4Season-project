## 1. 제품 정의와 포지셔닝

### 1.1 한 줄 정의

**투자의 사계는 주식 투자 초보자를 위한 모의투자 기반 투자 일지 앱입니다.**

### 1.2 이 제품이 하려는 일

이 제품의 목적은 사용자가 수익을 내게 하는 것이 아닙니다. **자신의 판단과 자신의 행동 사이에 얼마나 큰 차이가 있는지를 숫자로 보게 하고, 거기서 얻은 교훈을 다음 투자에 실제로 쓰게 만드는 것**입니다.

대부분의 투자 초보자는 판단이 틀려서가 아니라 자기가 세운 계획을 지키지 못해서 손실을 봅니다. 그런데 결과를 안 뒤에는 기억이 재구성되기 때문에 본인은 이 사실을 알아차리지 못합니다. "그때는 팔 수밖에 없었다"고 기억하지, "팔겠다고 적어두고 안 팔았다"고 기억하지 않습니다.

### 1.3 핵심 메커니즘 — 고정 → 대조 → 재사용

```
① 고정    결과를 알기 전에 판단 근거를 고정시켜 둔다
             (가설 기록 — 조건과 그때 할 일 — 9장)
              ↓
② 대조    결과가 나온 뒤 그것과 대조하게 한다
             (청산 회고, 계획과 실제의 차이 — 7장·9장)
              ↓
③ 재사용   거기서 나온 교훈을 다음 투자의 행동 지점에 다시 꺼내 놓는다
             (깨달은 것, 투자 수칙 — 10장·11장)
```

**세 번째 단계가 특히 중요합니다.** 기록만 쌓이고 다시 꺼내 쓰이지 않으면 일지는 그저 쌓인 글일 뿐이며, 사용자는 곧 쓰기를 멈춥니다.

**모든 기능은 두 가지 질문으로 판단합니다.**

1. 이 기능이 위 세 단계에 기여하는가?
2. 이 기능이 운영자의 손을 필요로 하는가?

### 1.4 이 제품이 하지 않는 것 (확정)

| 하지 않는 것 | 이유 |
| --- | --- |
| 실제 주문 체결 | 증권사 앱이 아닙니다 |
| 실시간 시세와 호가 제공 | 일별 시가·종가만 다룹니다 |
| 특정 종목의 매수·매도 권유 | 규제 문제이자 제품 정체성 문제입니다 |
| 수익률 랭킹, 사용자 간 성과 비교, 소셜 피드 | 비교는 남과 하는 것이 아니라 어제의 나와 하는 것입니다 |
| 뉴스 기사·애널리스트 리포트 본문 재생산 | 저작권 문제가 발생합니다 |
| 시장 전망·투자 전략 콘텐츠 제작 | **콘텐츠를 만들기 시작하면 이 서비스는 1인이 운영할 수 없게 됩니다** |
| **해외 주식** | 종목 풀은 전부 국내 상장 주식이며, '증시 개장일'과 '투자 주체별 수급'은 모두 국내 시장 기준입니다 |

콘텐츠 항목이 가장 중요합니다. 이 한 줄이 이 제품의 기능 구성 전체를 결정합니다.

**종목 풀 30개 선정은 이 원칙의 유일한 예외입니다.** 운영자가 연 1회 분석해 선정하며(15.1절), 그 대가로 발생하는 리스크는 17.3절에 따로 적었습니다.

### 1.5 '사계'라는 이름에 대하여 (확정)

**'사계'는 달력 연도와 정확히 일치하는 투자 사이클을 뜻합니다.**

2026년 다이어리를 사서 그 해만 쓰고 2027년에는 새 다이어리를 사는 것과 같은 구조입니다. 그리고 다이어리처럼 **연중 아무 때나 쓰기 시작할 수 있지만, 12월에는 모두 함께 덮습니다.**

| 다이어리 | 이 제품 |
| --- | --- |
| 2026년 다이어리는 2026년에만 쓴다 | 사이클은 그 해 12월 결산일에 닫힌다 |
| 3월에 사서 쓰기 시작해도 된다 | 연중 아무 때나 시작할 수 있다 |
| 다음 해에는 새 다이어리를 산다 | 계좌는 초기화되고 새 사이클이 열린다 |
| 지난 다이어리는 버리지 않는다 | 기록과 수칙은 영구히 누적된다 (13.3절) |

**봄·여름·가을·겨울에 투자 단계를 대응시키는 계절 비유는 도입하지 않습니다.** 화면 명칭, 기능 이름, 안내 문구 어디에도 계절 어휘를 쓰지 않습니다.

### 1.6 포지셔닝

이 제품은 투자 정보 앱이 아니라 **기록 앱에 가깝습니다.** 정보의 양이나 시세의 정확도로 경쟁하지 않고, 사용자가 부담 없이 기록을 남기고 그 기록이 다음 행동에 실제로 영향을 미치는가로 경쟁합니다.

따라서 참고해야 할 대상은 투자 정보 앱보다 **습관 형성 앱의 리텐션 설계**와 **기록을 다시 꺼내 쓰게 만드는 노트 앱**입니다. 기록·일지 앱과 명상 앱의 입력 마찰 처리 방식도 함께 참고합니다.

이 제품의 성패는 투자 기능의 완성도가 아니라, 사용자가 계속 쓰게 되는가에 달려 있습니다.

## 2. 타겟 사용자와 해결할 문제

### 2.1 타겟

**주식 투자 경험이 없거나 1~2년 이내인 개인 투자자.**

증권 계좌가 아직 없는 사람도 포함됩니다. 이 사실이 8장의 확인 버튼 문구를 결정합니다.

### 2.2 해결할 문제와 우선순위

| # | 문제 | 이 제품의 위치 |
| --- | --- | --- |
| 1 | **종목 발굴의 막막함** — 무엇부터 봐야 할지 모른다 | 부수적 |
| 2 | **감정에 따른 매매** — 공포에 팔고 탐욕에 산다. 특히 계획을 세워놓고도 지키지 못한다 | **직접 해결** |
| 3 | **신호와 소음의 미구분** — 중요한 소식은 흘려보내고, 중요하지 않은 소식에 과잉 반응한다 | 부수적 |
| 4 | **내러티브와 넘버스 변화의 미인지** — 기업의 성장 스토리와 실적·기업가치 전망이 바뀌었을 때 판단에 반영하지 못한다 | 부수적 |
| 5 | **회고의 부재** — 매매 후 무엇을 배웠는지 정리하지 않아 같은 실수를 반복한다 | **직접 해결** |
| 6 | **교훈의 사장** — 어쩌다 무언가를 깨달아도 기록해 두지 않거나, 기록해 두어도 정작 필요한 순간에 꺼내 보지 못한다 | **직접 해결** |

### 2.3 우선순위를 지켜야 하는 이유

**2번·5번·6번이 이 제품이 직접 해결하는 문제**이고, 1번·3번·4번은 그 과정에서 부수적으로 개선됩니다.

이 우선순위는 반드시 유지해야 합니다. **3번·4번을 직접 해결하려 들면 매일 콘텐츠를 만들어야 하고, 그 순간 운영이 불가능해집니다.**

- 3번(신호와 소음)을 직접 해결하려면 뉴스를 분류해 줘야 합니다 → 매일 콘텐츠 제작
- 4번(내러티브·넘버스)을 직접 해결하려면 실적 전망을 정리해 줘야 합니다 → 유료 데이터 + 매일 콘텐츠 제작

**1번(종목 발굴)만 예외적으로 부분 해결합니다.** 운영자가 연 1회 분석해 30개로 좁혀 주기 때문입니다. 이것이 가능한 이유는 **연 1회로 끝나는 작업**이기 때문이고, 3번·4번은 매일 발생하기 때문에 불가능합니다.

**빈도가 기준입니다.** 연 단위 작업은 채택하고, 일 단위 작업은 채택하지 않습니다.

3번과 4번은 **부수적 경로**로 접근합니다. 사용자가 스스로 판단한 것을 나중에 대조해 보게 해서 (15.4절) 개선합니다. 서비스가 답을 주는 대신 사용자가 자기 답을 검증하게 합니다.

## 3. 운영 제약과 비용 구조

이 장은 이후 모든 기능의 전제입니다. 이 문서의 각 기능 설명은 이 제약을 만족하는지 점검하며 작성되었습니다.

### 3.1 운영 인력 제약 (확정)

| 항목 | 기준 |
| --- | --- |
| 운영 인력 | 최대 3명, 실질적으로 1명 |
| 운영자가 **매일** 해야 하는 일 | **0** |
| 운영자가 주기적으로 해야 하는 일 | **사이클 시작 시점의 종목 풀 확정 등 연 단위 작업으로 한정** |
| 상시 운영 부담 총합 | **주당 2시간 초과 시 그 기능 구성은 실패** |

종목 풀 선정은 이 제약의 세 번째 줄에 정확히 해당합니다. **연 1회이고, 사이클이 달력 연도와 일치하므로 모든 사용자가 같은 목록을 씁니다.**

### 3.2 기능 채택 기준 (확정)

새 기능을 검토할 때 아래 세 질문에 모두 답할 수 있어야 채택합니다.

1. **이 기능이 유지되기 위해 사람이 무엇을 해야 하는가?** — 답이 "정기적으로 무언가를 만들어야 한다"이면 탈락. 단 **연 1회 작업은 허용**합니다
2. **사용자가 0명일 때 이 기능 때문에 나가는 돈이 있는가?**
3. **이 기능이 없으면 "고정 → 대조 → 재사용"이라는 핵심 경험이 훼손되는가?**

### 3.3 비용 구조

| 항목 | 성격 | 통제 방법 |
| --- | --- | --- |
| 일별 시세 데이터 | 고정비 | 종목 풀 30개로 한정. 실시간 미사용, 일 1회 종가만 수집 |
| 공시 발생 목록 | 고정비 | 공개 시스템 이용을 전제. **발생 사실과 원문 링크만 가져오고 본문을 저장·가공하지 않음** |
| 서버·인프라 | 준고정비 | 실시간 처리 없음. 일 1회 배치와 사용자 요청 시점 계산만 |
| 알림 발송 | 사용자 비례 | 하루 1건 이내로 제한 |
| 결산 리포트 생성 | 사용자 비례, 사이클당 1회 | 집계는 전부 자동 계산. 문장 생성이 필요한 부분만 최소 범위로 한정 |
| **종목 풀 분석·선정** | **연 1회 사람 작업** | **연 1회로 한정. 사용자 수와 무관하며 전 사용자가 같은 목록을 씀** |
| 그 외 콘텐츠 제작 | **0이어야 함** | 서비스는 사실 데이터만 전달하고 해석은 사용자가 함 |
| 고객 응대 | **최소화** | 사용자가 스스로 정정·삭제할 수 있게 설계 |

**고정비는 데이터 두 종류뿐입니다.** 시세와 공시. 둘 다 종목 풀 30개로 범위가 묶여 있고, 공시는 본문을 저장하지 않으므로 부담이 가장 작은 형태입니다.

**사람 작업은 종목 풀 분석 하나뿐이고, 연 1회입니다.** 이것이 이 제품에서 유일하게 허용된 콘텐츠성 작업이며, 15.1절과 17.3절에서 그 조건과 대가를 다룹니다.

### 3.4 운영자가 실제로 하는 일의 전부

| 주기 | 하는 일 | 예상 부담 |
| --- | --- | --- |
| **연 1회 (연말~연초)** | **다음 사이클의 종목 풀 30개 분석·선정** | 수일 |
| 연 1회 | 그 해의 정기 조정일 3개와 결산일이 달력 규칙대로 산출됐는지 확인 | 30분 이내 |
| 최초 1회 | 정기 조정일 달력 규칙 확정 | 초기 작업 |
| 최초 1회 | 연습 모드용 과거 구간 데이터 준비 | 초기 작업 |
| 최초 1회 | 배지 문구, 조건 선택지, 태그 목록, 수칙 문장 틀, 설문 문항 작성 | 초기 작업 |
| 상시 | 장애 대응, 문의 응대 | 최소화 설계로 통제 |

**매일 해야 하는 일도, 매주 해야 하는 일도 없습니다.** 시세·공시 수집, 조건 도달 판정, 알림 발송, 계좌 계산, 결산 리포트 생성은 전부 자동입니다.

**연 1회 작업이 연말에 몰려 있다는 점이 중요합니다.** 사이클이 달력 연도와 일치하므로 종목 풀 분석은 12월~1월에 한 번만 하면 되고, 나머지 열한 달은 사람 손이 필요 없습니다. 사용자마다 사이클이 다르게 돌아가는 구조였다면 이 작업이 상시화되어 불가능했을 것입니다.

## 5. 핵심 개념 및 용어 정의

### 5.1 용어

| 용어 | 정의 |
| --- | --- |
| **종목 풀** | 그 해에 운영자가 분석해 제시하는 30개 관찰 대상 종목 목록. **한 해 동안 모든 사용자가 같은 목록을 씁니다** |
| **포인트** | 모의투자 화폐 단위. 현실의 '원'과 1:1로 정확히 대응 |
| **사이클** | **달력 연도 단위 기간.** 연중 아무 때나 시작할 수 있으나, **그 해 12월 결산일에 모든 사용자가 함께 끝납니다** |
| **규칙 투자** | 사전에 정해진 규칙에 따라 **기계적으로 진행되는** 트랙 |
| **자유 투자** | 사용자가 자유롭게 판단하여 **매매를 기입하는** 트랙 |
| **가설 기록** | 매수 시점에 남기는 판단 근거. 논리 / 되돌아볼 조건 / 그때 할 일 / 목표 / 예상 보유 기간 |
| **되돌아볼 조건** | "무엇이 사실로 드러나면 내 판단이 틀린 것인가"에 대한 사전 선언. **그 자체로는 매도를 뜻하지 않음** |
| **그때 할 일** | 되돌아볼 조건에 닿았을 때 무엇을 할지 **매수 시점에 미리 정해 둔 대응**. 전량 매도 / 절반 매도 / 그대로 보유 중 하나 |
| **내 계획대로 계좌** | 사용자가 매수 시점에 미리 정해 둔 '그때 할 일'을 조건 도달 시 그대로 집행했을 경우의 가상 계좌 |
| **그냥 둔 계좌** | 최초 매수한 종목을 결산일까지 아무것도 하지 않고 보유했을 경우의 가상 계좌 |
| **계획과 실제의 차이** | 내 계획대로 계좌 − 자유 투자 계좌. 계획을 지키지 못해 생긴 손익 차이 |
| **내 계획 지킨 비율** | (자유 투자) 되돌아볼 조건에 도달했을 때, 미리 정해 둔 '그때 할 일'대로 행동한 비율 |
| **규칙 실행 확인율** | (규칙 투자) 정기 조정일에 "이대로 하겠습니다"를 누른 비율 |
| **비상 선언** | 시장에 심각한 일이 벌어지고 있다고 사용자가 판단해 그 사실과 이유를 기록하는 행위. **계좌를 움직이지 않음** |
| **깨달은 것** | 일지나 회고 중 사용자가 따로 표시해 두는 한 줄짜리 교훈 |
| **투자 수칙** | 사이클 종료 시 사용자가 확정하는, 다음 사이클에 적용할 자기 규칙 |
| **올해의 투자 레슨** | 한 사이클의 기록 전체를 종합해 결산 시점에 제공하는 회고 문서 |

### 5.2 사이클은 달력 연도입니다 (확정)

| 항목 | 내용 |
| --- | --- |
| 시작 | **연중 아무 때나.** 사용자가 온보딩을 마치고 첫 매수를 기입한 날 |
| 종료 | **그 해 12월 결산일. 모든 사용자가 같은 날 끝납니다** |
| 길이 | 시작 시점에 따라 **1~12개월**로 달라집니다 |
| 다음 사이클 | 다음 해 새 종목 풀로 새로 시작 |

**연중 가입을 허용하면서 종료일을 고정하는 이유**는 1.5절의 다이어리 원칙 때문입니다. 3월에 다이어리를 사도 그 다이어리는 12월에 끝납니다.

**이 구조가 만들어내는 두 가지 결과**

1. **종목 풀을 연 1회만 만들면 됩니다.** 3월 가입자도 1월 가입자와 같은 30개를 봅니다. 이것이 운영자 분석 선정을 가능하게 하는 유일한 조건입니다 (3.4절).
2. **가입 시점에 따라 남은 정기 조정 횟수가 달라집니다.** 이 문제는 8.3절에서 다루고, 처리 방식은 미결입니다 → 18.5, 18.6

### 5.3 되돌아볼 조건과 '그때 할 일'을 반드시 구분할 것 (확정 — 매우 중요)

**'되돌아볼 조건'은 손절선이 아닙니다.** 손절은 손실을 끊는 행위이고, 되돌아볼 조건은 **판단을 다시 검토해야 하는 시점**을 뜻합니다. 조건에 닿았을 때 파는 것도, 다시 살펴본 뒤 그대로 두는 것도 모두 정당한 선택입니다.

그런데 이 진술만 있으면 '내 계획대로 계좌'를 계산할 수 없습니다. 조건에 닿았을 때 무엇을 하는지가 정해져 있지 않기 때문입니다. 그래서 **조건과 대응을 두 칸으로 분리하되, 대응도 매수 시점에 미리 받습니다.**

```
[ 목표가 대비 15% 하락 ] 하면 → [ 전량 판다 ]
        조건                        그때 할 일
```

| 칸 | 성격 | 하는 일 |
| --- | --- | --- |
| **앞칸 (조건)** | 인식의 문제 | 도달하면 재검토 알림이 갑니다 |
| **뒷칸 (그때 할 일)** | 행동의 문제 | **'그대로 보유'도 정당한 선택지로 명시적으로 존재합니다** |

이렇게 하면 "팔 수도 있고 그대로 둘 수도 있다"는 원칙이 그대로 유지되면서, **그 선택을 결과를 알기 전에 하라**는 뜻이 됩니다.

조건에 닿은 뒤에 그때 가서 정하는 것은 계획이 아니라 반응이며, **그것은 이미 '자유 투자 계좌'가 측정하고 있습니다.**

### 5.4 '지킨 비율'은 하나의 숫자가 아닙니다 (확정)

두 트랙에서 일어나는 일은 성격이 전혀 다르므로 **절대 하나의 숫자로 합치지 않습니다.**

| | **규칙 실행 확인율** | **내 계획 지킨 비율** |
| --- | --- | --- |
| 어느 트랙 | 규칙 투자 | 자유 투자 |
| 분모 | 그 사용자에게 남아 있던 정기 조정일 수 (고정) | 되돌아볼 조건에 도달한 건수 (가변) |
| 측정하는 것 | 시키는 대로 하는가 | 내가 정한 대로 하는가 |
| 낮을 때의 원인 | 알림을 못 봄, 귀찮음, 앱을 안 엶 | 손실 회피, 미련, 공포 |
| 낮을 때의 처방 | 알림과 흐름 설계를 고침 | 조건 설계나 심리를 다시 봄 |

**분모가 3인 것과 15인 것을 뭉개면 어느 쪽이 문제인지 알 수 없게 됩니다.** 이 서비스의 최종 산출물인 투자 수칙은 "무엇을 고쳐야 하는가"에서 나오는데, 합쳐진 숫자로는 고칠 대상을 특정할 수 없습니다.

두 숫자는 모든 화면과 리포트에서 **각각 별개의 이름으로** 표시되어야 하며, **'지킨 비율'이라는 모호한 표현은 어디에도 쓰지 않습니다.**

> 연중 가입자는 정기 조정일 수가 3회보다 적을 수 있으므로, **규칙 실행 확인율은 항상 "n회 중 m회"로 분모를 함께 표시합니다.**

## 7. 계좌 구조와 성과 비교 체계

### 7.1 왜 필요한가

이 장은 이 제품의 **핵심 산출물**을 다룹니다.

사용자에게 "당신은 계획을 안 지켰습니다"라고 말하는 것은 아무 효과가 없습니다. 사용자는 자기가 계획을 안 지켰다고 생각하지 않기 때문입니다. **"계획대로 했다면 +14.2%, 실제로는 +3.1%였습니다"라는 숫자만이 그 인식을 바꿉니다.**

**유도하는 행동**: 매수 시점에 조건과 '그때 할 일'을 성실히 남기게 됩니다. 그것이 없으면 '내 계획대로 계좌'가 계산되지 않고, 그러면 이 비교 자체가 성립하지 않기 때문입니다.

### 7.2 4개 계좌 (확정)

사용자는 한 사이클에서 **4개의 성과 곡선**을 비교합니다. 이 중 **사용자의 행동이 반영되는 것은 '자유 투자 계좌' 하나뿐**입니다. 나머지 셋은 모두 기준선이며, 사용자가 무엇을 하든 달라지지 않습니다.

| 계좌 | 사용자 행동 반영 | 무엇을 보여주는가 | 짝이 되는 계좌 |
| --- | --- | --- | --- |
| **규칙 투자 계좌** | **없음** | 정해진 규칙을 따랐다면 | (규칙 실행 확인율과 함께 읽음) |
| **내 계획대로 계좌** | 매수 시점의 사전 선언만 | 내가 세운 계획을 지켰다면 | 자유 투자 계좌 |
| **자유 투자 계좌** | 전부 | 실제로 내가 한 것 | 내 계획대로 계좌 |
| **그냥 둔 계좌** | **없음** | 아무것도 안 했다면 | 모든 계좌의 공통 바닥선 |

**짝 관계를 화면에서도 드러냅니다.** '내 계획대로 계좌'는 자유 투자 계좌의 짝이며, **규칙 투자 계좌와는 직접 대응하지 않습니다.** 가설 기록은 자유 투자 종목에만 작성하므로, 이 계좌는 자유 투자 트랙에서만 파생됩니다.

**이 구분이 4개 계좌 구조 전체를 지탱합니다.** 기준선 중 하나라도 사용자 행동에 반응하면 비교 대상이 사라지고, 이 제품의 핵심 산출물이 성립하지 않습니다.

'내 계획대로 계좌'와 '그냥 둔 계좌'는 **매수 시점 이후 사용자에게 추가 입력을 요구하지 않습니다.** 매수할 때 받은 조건과 대응이 완결된 매매 규칙을 이루므로, 일별 종가만으로 계산됩니다.

> **유지에 필요한 사람의 일: 없음.** 네 계좌 모두 일별 종가와 사용자가 이미 입력한 데이터만으로 자동 계산됩니다.

### 7.3 시작 조건 (확정)

| 항목 | 내용 |
| --- | --- |
| 지급 | 규칙 투자와 자유 투자에 **각각 3,000만 포인트** (총 6,000만 포인트) |
| 최초 매수 | 선택한 종목에 **균등 배분** |
| 그냥 둔 계좌 기준 | **3,000만 포인트.** 두 실제 계좌 각각과 비교되어야 하므로 6,000만이 아님 |

**균등 배분으로 고정하는 이유**는 네 계좌의 시작 조건이 같아야 비교가 성립하고, 비중 결정이라는 판단을 온보딩에 하나 더 얹지 않기 위함입니다.

**시작 종목 수는 가입 시점에 따라 달라질 수 있습니다** (5.2절, 8.3절). 종목 수가 정해지면 종목당 금액은 3,000만 ÷ 종목 수로 자동 결정됩니다. 예를 들어 10종목이면 종목당 300만 포인트입니다.

> 시작 종목 수를 어떻게 정할지는 미결 사항입니다. → 18.5

### 7.4 규칙 투자 계좌는 사용자 행동과 무관하게 진행됩니다 (확정)

**규칙 투자 계좌는 사용자가 알림을 확인하든 하지 않든, 앱을 열든 열지 않든 정해진 날짜에 정해진 규칙대로 자동으로 진행됩니다.** 조정일이 지나면 이 계좌의 종목 수는 줄어듭니다. 사용자가 아무 동작도 하지 않아도 그렇습니다.

**확인 버튼은 계좌를 움직이는 장치가 아니라 사용자를 측정하는 장치입니다.** 확인 여부는 '규칙 실행 확인율'로만 남고 계좌 성과에는 영향을 주지 않습니다.

**이렇게 정하는 이유 세 가지**

1. 규칙 계좌가 사용자 행동에 반응하면 **기준선이 사라지고 4개 계좌 비교가 무너집니다.**
2. 확인을 한 번도 하지 않은 사용자의 규칙 계좌는 결산까지 최초 종목을 그대로 들고 가게 되어 **'그냥 둔 계좌'와 완전히 같아집니다.** 계좌 하나가 통째로 중복됩니다.
3. 알림을 못 봤거나 그날 바빴다는 사정이 성과 곡선에 섞여 들어가면, 그것은 학습이 아니라 잡음입니다.

### 7.5 내 계획대로 계좌의 집행 규칙 (확정)

이 계좌는 이 제품의 **유일한 핵심 산출물**이므로, 어떤 경우에 무엇을 하는지 예외 없이 정의합니다.

**기본 원칙**

> 이 계좌는 **사용자가 매수 시점에 미리 정해 둔 대응만** 집행합니다. **사용자가 미리 정하지 않은 행동은 절대 하지 않습니다.**

서비스가 판단을 대신 내리는 순간 이 계좌는 "당신이 이렇게 했어야 한다"는 조언이 되어버립니다.

**상황별 집행 내용**

| 상황 | 집행 내용 |
| --- | --- |
| 되돌아볼 조건 도달 | 매수 시 정해 둔 '그때 할 일'을 **그날 종가로 집행** |
| '그때 할 일'이 '그대로 보유'인 경우 | **아무것도 하지 않고 계속 보유** |
| 목표 도달 | 목표를 입력했다면, 그 목표에 대해서도 '그때 할 일'을 함께 받아 그대로 집행 |
| 예상 보유 기간 만료 | **기본은 계속 보유.** 사용자가 '기간이 끝나면 판다'를 선택한 경우에만 매도 |
| 아무 조건에도 닿지 않음 | 결산일에 전량 매도 |
| 부분 매도 후 잔여 물량 | 새 조건이 없으면 결산일까지 보유 |
| 매도 대금 | **현금으로 보유하며 재투자하지 않음** |
| 조건을 정하지 않은 매수 | 결산일까지 보유. 해당 종목에 한해 **'그냥 둔 계좌'와 같아짐** |

**세부 규칙 (확정)**

| 규칙 | 내용 |
| --- | --- |
| **우선순위** | 두 조건이 같은 날 충족되면 **매도 비중이 큰 쪽을 먼저 집행**합니다 |
| **자동 판정이 불가능한 조건** | "실적 전망이 하향되면"처럼 가격으로 판정할 수 없는 조건은 **사용자가 도달했다고 표시한 날의 종가**를 기준으로 집행합니다. **사용자가 끝까지 표시하지 않으면 그 조건은 집행되지 않습니다** |
| **측정 편향의 존재** | 위 규칙 때문에 **자기 보고 조건은 차이가 실제보다 작게 측정될 수 있습니다.** 이 한계를 사용자에게 안내해야 합니다 |

측정 편향을 어떻게 다룰지는 미결 사항입니다. → 18.11

**왜 이렇게까지 세밀하게 정의하는가**

이 계좌 하나가 이 제품의 존재 이유이기 때문입니다. 여기에 정의되지 않은 상황이 하나라도 있으면 그 순간 시스템이 임의로 판단하게 되고, 그것은 사용자가 하지 않은 결정을 사용자의 것인 양 계산에 넣는 일이 됩니다.

### 7.6 조건은 종목 단위로 하나만 살아 있습니다 (확정)

같은 종목을 여러 번 나눠 사면 가설 기록이 여러 개 생깁니다. 조건이 여러 개 동시에 살아 있으면 위의 우선순위 규칙이 감당할 수 없을 만큼 복잡해지고, 사용자도 자기 조건이 몇 개인지 알 수 없게 됩니다.

| 항목 | 처리 |
| --- | --- |
| 가설 기록 | **매수 건마다 별도로** 남김. 그때의 논리·기분·확신도가 다르기 때문 |
| 되돌아볼 조건 | **가장 최근 매수 건의 조건**이 그 종목 전체 보유분에 적용 |
| 이전 조건 | 기록으로는 남되 판정에서는 비활성 |
| 추가 매수 시 | "기존 조건을 그대로 둘까요, 새로 정할까요?"를 한 번 물음 |

### 7.7 거래비용과 세금 (확정)

| 규칙 | 내용 |
| --- | --- |
| 적용 범위 | **네 계좌 모두에 동일한 매매 비용을 반영합니다.** 실제 계좌에만 비용이 없으면 자유 투자가 구조적으로 유리해져서, 계획과 실제의 차이가 실제보다 작게 나옵니다 |
| 추가 보정 | 그 위에, **가상 계좌가 조건 도달로 집행할 때만** 체결 오차를 추가로 불리하게 반영합니다. 현실에서는 종가에 정확히 체결되지 않기 때문이며, 가상 계좌를 실제보다 좋아 보이게 만들지 않기 위함입니다 |
| 요율 관리 | 수수료율과 세율은 **설정값으로 관리**합니다. 법 개정에 대응해야 합니다 |
| 공개 | 적용한 비용 기준을 **사용자가 확인할 수 있어야** 합니다 |

이 순서가 중요합니다. 먼저 네 계좌에 같은 비용을 넣고, 그 위에 가상 계좌에만 체결 오차를 얹습니다.

### 7.8 종목에 사고가 생겼을 때 (확정)

확률은 낮지만 반드시 일어나며, **네 계좌 전부에 영향을 줍니다.** 절차를 미리 정해 이용약관에 넣습니다.

| 상황 | 처리 |
| --- | --- |
| 단기 거래정지 | 정지 직전 종가로 평가를 고정. **조건 판정 중단.** 정기 조정의 매도 대상에서 제외 |
| 장기 정지 / 상장폐지 결정 | 정지 직전 종가로 **네 계좌 모두 일괄 정리**하고 사용자에게 안내 |
| 합병·분할·액면분할 | 수량과 단가를 조정한 뒤 안내 |
| **예방** | 종목 풀 선정 단계에서 관리종목·투자경고 등을 **사전에 제외** |

**마지막 줄이 가장 중요합니다. 선정 단계에서 걸러내는 것이 최선의 대응입니다.** 종목 풀이 운영자 분석으로 선정되므로(15.1절), 이 배제는 분석 과정에 반드시 포함되어야 합니다.

**한 해 동안 목록이 고정되므로 사고 종목을 중간에 교체하지 않습니다.** 교체하면 사용자마다 다른 목록을 보게 되고, 이미 그 종목을 산 사용자와 안 산 사용자의 조건이 달라집니다.

### 7.9 무슨 일이 있었는지 항목별로 보여주기

총 차이만 보여주면 사용자는 고개만 끄덕이고 행동은 바뀌지 않습니다. **어떤 행동이 얼마를 만들었는지 항목별로 나눠서** 보여줘야 합니다.

**측정하는 것은 "팔았어야 하는데 안 팔았다"가 아니라 "내가 하기로 한 것과 실제로 한 것이 달랐다"입니다.** 따라서 항목은 반드시 **양방향 대칭**이어야 합니다.

| 항목 | 판정 조건 |
| --- | --- |
| **판다고 해놓고 안 팔았다** | '전량/절반 매도'를 정해 둔 조건에 도달했는데 계속 보유 |
| **보유한다고 해놓고 팔았다** | '그대로 보유'를 정해 둔 조건에 도달했는데 매도 |
| **조건에 닿기 전에 팔았다** | 어떤 조건에도 닿지 않았는데 매도 |
| **계획에 없던 추가 매수** | 가설 기록 없이 추가로 매수 |
| **갑자기 산 것** | 가설 기록이 아예 없는 매수 |

**두 번째 항목을 첫 번째와 같은 무게로 집계하는 것이 중요합니다.** 매도 쪽만 세면 앱이 "닿으면 파는 것이 정상"이라고 은근히 말하게 되며, 이는 특정 매매 행위를 권하는 것과 다르지 않습니다.

**세 개의 차이 (제품의 핵심 산출물)**

| 계산 | 이름 | 의미 |
| --- | --- | --- |
| 내 계획대로 계좌 − 자유 투자 계좌 | **계획과 실제의 차이** | "판단은 맞았는데 실행이 어긋나서 생긴 차이." 이 제품이 존재하는 이유입니다 |
| 자유 투자 계좌 − 그냥 둔 계좌 | **내가 움직여서 만든 차이** | "내가 한 모든 매매가 만들어낸 결과." 음수일 수 있고, 그 사실 자체가 중요한 정보입니다 |
| 내 계획대로 계좌 − 그냥 둔 계좌 | **내 계획 자체가 좋았는가** | 첫 번째 차이와 **반드시 분리해서 표시**합니다 |

**세 번째를 분리하는 이유**: 계획이 나빴던 것과 계획을 안 지킨 것은 완전히 다른 이야기입니다. 이 둘을 섞어 보여주면 사용자는 잘못된 교훈을 얻습니다.

**문구는 담백하게 씁니다.**

> 이번 사이클에서 계획대로 했다면 +14.2%, 실제로는 +3.1%였습니다.
> 차이의 절반 이상(7.4%p)이 '판다고 해놓고 안 팔았다' 4건에서 나왔습니다.

이 항목별 내역은 **11장의 투자 수칙을 만들 때 가장 중요한 재료**가 됩니다.

**표시 단위 (확정)**

| 규칙 | 내용 |
| --- | --- |
| 기본 단위 | **퍼센트포인트**를 기본으로 하고, **포인트 금액을 괄호로 병기**합니다. 예: `7.4%p (740,000포인트)` |
| 이유 | 사용자가 자기 실제 계좌 금액에 대입해 볼 수 있고, 사이클 간 비교도 가능하기 때문 |
| 기준일 표기 | 모든 성과 화면에 **"○월 ○일 종가 기준"** 을 항상 표기합니다 |
| **기간 표기** | 사이클 길이가 사용자마다 다르므로, **"○개월 기준"** 을 함께 표기합니다 |

이 서비스는 하루 한 번 종가만 수집하므로, **장중에 앱을 열면 직전 영업일 종가 기준 수치가 보입니다. 이 사실을 감추지 않습니다.**

장중 실시간 수치를 제공하지 않는 것은 비용 문제이기도 하지만, **장중 호가를 들여다보는 경험 자체를 이 제품이 권장하지 않기 때문**이기도 합니다.

> **유지에 필요한 사람의 일: 없음.** 판정 조건이 전부 기계적이라 자동 집계됩니다.

### 7.10 배지 (재미 요소)

위 항목들을 **자조적인 이름의 배지**로도 제공합니다.

| 배지 예시 | 무엇을 세는가 |
| --- | --- |
| 존버 장인 | 판다고 해놓고 안 판 횟수 |
| 마음이 바뀜 | 보유한다고 해놓고 판 횟수 |
| 조기 은퇴 | 조건에 닿기 전에 판 횟수 |
| 심야의 결단 | 밤에 가설 없이 산 횟수 |

**배지도 양방향 대칭이어야 합니다.** '존버 장인'만 있고 그 반대가 없으면, 배지 체계 자체가 "파는 것이 정상"이라고 말하게 됩니다. 양쪽 이름의 톤도 서로 맞춰야 합니다.

**지켜야 할 점 (확정)**

| 원칙 | 내용 |
| --- | --- |
| 놀림이 아니라 자기 인식 장치 | 문구가 사용자를 무시하는 느낌을 주면 안 됩니다 |
| 획득 조건 사전 공개 | 숨겨진 조건은 두지 않습니다 |
| 숨기기·끄기 가능 | 사용자가 자기 배지를 숨기거나 **배지 기능 자체를 끌 수 있어야** 합니다 |
| **긍정 배지도 함께 둔다** | 미리 정한 대응대로 행동한 횟수, 기록 연속일, 수칙을 지킨 횟수 |
| 비교·순위 없음 | 다른 사용자와 비교하거나 공개 순위를 만들지 않습니다 |

**왜 필요한가**: 숫자만으로는 자기 패턴이 각인되지 않습니다. 이름이 붙으면 기억에 남습니다. **유도하는 행동**: 다음 매매에서 "또 조기 은퇴 하는 건가"라고 스스로 묻게 됩니다.

> **유지에 필요한 사람의 일: 최초 배지 문구 작성 1회.**

## 8. 규칙 투자 트랙

### 8.1 왜 필요한가

규칙 투자는 **비교 기준선**입니다. 사용자에게 "정해진 대로만 하면 어떻게 되는가"를 보여줍니다.

**유도하는 행동**: 정해진 날에 무슨 일이 일어나는지 지켜보고 그것을 자기 판단과 비교하게 됩니다. 그리고 확인 버튼을 누를지 말지를 스스로 결정하게 됩니다.

### 8.2 기본 원칙 (확정)

| 항목 | 내용 |
| --- | --- |
| 초기 자금 | 사이클 시작 시 **3,000만 포인트**를 지급하고, 선택한 종목에 **균등 배분** |
| 종료 | **그 해 12월 결산일에 전 종목 매도**하여 손익 확정 |
| 가설 기록 | **이 트랙에서는 작성하지 않습니다.** 종목 선택 외에 사용자의 판단이 개입하지 않기 때문입니다 |

마지막 항목이 7.2절의 짝 관계를 설명합니다. 가설 기록이 없으므로 '내 계획대로 계좌'는 이 트랙에서 파생될 수 없습니다.

### 8.3 사이클과 매매일 (확정)

**사이클은 달력 연도입니다.** 연중 아무 때나 시작할 수 있고, **그 해 12월 결산일에 모든 사용자가 함께 끝납니다.**

매매일은 **운영자의 시장 판단이 아니라 사전에 공개된 달력 규칙으로 자동 산출**합니다. 예를 들어 "분기별 선물·옵션 만기일 다음 거래일"처럼 누구나 계산할 수 있고 매년 동일하게 적용되는 기준을 씁니다.

**그 해의 매매일은 전 사용자 공통입니다.**

| 구분 | 횟수 | 시점 |
| --- | --- | --- |
| 정기 조정 | 최대 3회 | 그 해의 분기 조정일 중 앞의 3개 |
| 최종 결산 | 1회 | 그 해의 **4번째 분기 조정일 (12월)** |

**가입 시점에 따라 남은 정기 조정 횟수가 달라집니다.**

| 가입 시점 | 겪게 되는 정기 조정 |
| --- | --- |
| 1차 조정일 이전 | 3회 |
| 1차 이후 ~ 2차 이전 | 2회 |
| 2차 이후 ~ 3차 이전 | 1회 |
| 3차 이후 | **0회** |

**이것이 개별 사이클 구조와 달력 연도 구조를 맞바꾸면서 생긴 대가입니다.** 남은 조정 횟수에 따라 시작 종목 수와 축소 경로를 어떻게 맞출지, 그리고 조정을 한 번도 겪지 못하는 늦은 가입자를 어떻게 할지가 결정되어야 합니다.

> 시작 종목 수와 축소 경로는 미결 사항입니다. → 18.5
> 늦게 가입한 사용자의 처리는 미결 사항입니다. → 18.6

사용자에게는 **사이클 시작 시점에 남은 매매일을 모두 미리 보여줍니다.**

**달력 연도 구조가 가능하게 하는 것**

한 해 동안 **모든 사용자가 같은 종목 풀과 같은 매매일을 씁니다.** 이것이 15.1절의 운영자 분석 선정을 성립시키는 조건입니다. 사용자마다 사이클이 다르게 돌아가는 구조였다면 종목 풀을 가입 시점마다 새로 만들어야 했고, 사람이 분석하는 방식은 불가능했을 것입니다.

**매매일에서 운영자 재량을 배제하는 이유 세 가지**

1. 사이클마다 운영자가 시장을 판단해야 하는 구조는 1~3인 운영과 맞지 않습니다.
2. 운영자가 시점을 고르면, 성과가 나쁠 때 그 책임이 운영자에게 돌아갑니다.
3. 시점 선택이 운영자의 재량이면 그 자체가 투자 판단을 제공하는 행위로 해석될 여지가 생깁니다.

**종목 선정에는 재량이 들어가지만 매매 시점에는 들어가지 않습니다.** 재량의 범위를 최소한으로 묶어 두는 것이 17.3절의 리스크 관리와 직결됩니다.

> 구체적인 달력 기준은 미결 사항입니다. → 18.3

> **유지에 필요한 사람의 일: 연 1회, 산출된 날짜 4개 확인.** 산출 자체는 자동입니다.

### 8.4 조정 규칙 (확정하되 명시적 단서 필요)

정기 조정일마다 **성과가 가장 나쁜 2개 종목을 매도하고, 그 금액을 나머지 종목에 균등 분산**합니다.

정기 조정을 3회 다 겪는 사용자의 경로는 다음과 같습니다.

| 회차 | 종목 수 변화 |
| --- | --- |
| 1차 | 10개 → 8개 |
| 2차 | 8개 → 6개 |
| 3차 | 6개 → 4개 |

**남은 조정 횟수가 적은 사용자의 경로는 18.5의 결정에 따릅니다.**

**'성과가 나쁘다'의 기준은 구간 수익률입니다.** 직전 조정일(1차의 경우 최초 매수일) 이후의 수익률을 기준으로 하위 2종목을 정리합니다.

누적 수익률이 아닌 이유는, 초반에 크게 빠졌다가 회복 중인 종목이 계속 정리 대상으로 남는 것을 피하고 **"직전 조정 이후 가장 부진했던 2종목"이 사용자에게 설명하기 쉽기** 때문입니다.

**동점 처리**: 누적 수익률이 낮은 쪽을 먼저 정리하고, 그것도 같으면 종목코드 순으로 처리합니다. 재현 가능한 기준이어야 합니다.

**이 기준을 사용자에게 반드시 공개합니다.** 어떤 기준을 고르느냐보다, **왜 이 종목이 정리되었는지 사용자가 확인할 수 있느냐**가 더 중요합니다.

**반드시 함께 안내해야 할 단서 (확정)**

> 이 규칙은 **수익률이 검증된 전략이 아니며**, 하락한 종목에 자금을 더 넣는 성격이 있습니다.

앱 안에서 사용자에게 이 점을 명시적으로 안내해야 합니다.

> 이 규칙은 **규칙을 지키는 경험을 제공하기 위한 예시 규칙**이며, 수익을 보장하지 않습니다.
> 아래 '그냥 둔 계좌'와 비교해 이 규칙이 실제로 나았는지 직접 확인해 보십시오.

**'그냥 둔 계좌'를 나란히 보여주는 이유 중 하나가 바로 이것입니다.**

이 로직을 MVP에서 유지할지는 미결 사항입니다. → 18.10

> **유지에 필요한 사람의 일: 없음.** 매도 대상 선정과 재분배가 전부 기계적으로 계산됩니다.

### 8.5 확인 버튼 (확정)

| 항목 | 내용 |
| --- | --- |
| 주문 버튼 | **앱 안에 매수·매도 주문 버튼이 없습니다** |
| 사용자가 하는 일 | 정기 조정일이 되면 알림이 오고, **"이대로 하겠습니다"를 누르는 동작만** 합니다 |
| 계좌와의 관계 | **이 확인은 계좌를 움직이지 않습니다.** 규칙 투자 계좌는 확인 여부와 무관하게 자동으로 진행됩니다 |

**버튼 문구를 "매매했음"이 아니라 "이대로 하겠습니다"로 하는 이유**

이 서비스의 타겟에는 **아직 증권 계좌가 없는 사람도 포함**되며, 앱은 사용자가 실제로 주문을 냈는지 알 수 없고 알 필요도 없습니다. **"이 매매를 하기로 했다"** 는 뜻으로 정의하면 계좌가 있든 없든 성립하고, "실제 주문 체결을 하지 않는다"는 원칙(1.4절)과도 일관됩니다.

| 항목 | 규칙 |
| --- | --- |
| 확인 가능 시각 | **제한 없음. 장중에도 가능** |
| 확인 가능 기한 | 다음 정기 조정일 전까지 |
| 성과 계산 기준일 | 확인한 날과 무관하게 **항상 조정일 종가** |
| 확인하지 않고 지나감 | 그대로 기록되며 **'규칙 실행 확인율'에만 반영**. 계좌 성과에는 영향 없음 |

**시각 제한이 필요 없는 이유는 확인이 계좌를 움직이지 않기 때문입니다.** 사용자에게도 이 점을 분명히 안내합니다.

> "이 계좌는 알아서 굴러갑니다. 확인 버튼은 계좌가 아니라 당신을 기록하는 것입니다."

**유도하는 행동**: 정해진 날에 "나는 이대로 할 것인가"를 스스로 결정하게 됩니다. 누르지 않는 것도 하나의 결정이고, 그 사실을 결산에서 마주하게 됩니다.

> **유지에 필요한 사람의 일: 없음.**

### 8.6 결산일은 확인 없이 자동 실행 (확정)

**결산일의 전량 매도에는 확인을 요구하지 않습니다.**

결산은 사용자의 선택 사항이 아니라 제품의 전제이며, 확인을 요구하면 앱을 열지 않은 사용자의 사이클이 닫히지 않아 **올해의 투자 레슨도 다음 사이클도 막힙니다.**

**결산일은 전 사용자 공통이므로 같은 날 모두의 사이클이 함께 닫힙니다.** 이것이 다이어리 은유의 마지막 조각입니다.

다만 결산이 끝난 뒤 **"실제 계좌에서도 정리하셨나요?"** 를 한 번 물어 실행 기록을 남깁니다. 이것은 결산을 막지 않으며, 답하지 않아도 됩니다.

### 8.7 비상 선언 (확정 — 계좌를 움직이지 않는 기록 기능)

예상치 못한 사건이 벌어졌다고 판단되면 사용자는 **비상 선언**을 할 수 있습니다. **연 2회로 제한**합니다.

**비상 선언은 계좌를 움직이지 않습니다.** 하는 일은 이것뿐입니다.

1. **"지금 심각한 일이 벌어지고 있다"고 판단한 시점과 이유를 기록**
2. **그 시점의 네 계좌 상태를 저장**

그 뒤 자유 투자 트랙에서 어떻게 대응할지는 사용자의 자유입니다. 자유 투자는 원래 언제든 기입할 수 있으므로 별도의 권한이 필요 없습니다.

**규칙 투자 계좌에는 어떤 예외도 적용되지 않습니다.** 사용자가 규칙 계좌를 중간에 뒤집을 수 있으면 그 계좌는 더 이상 기준선이 아니게 되고, 확인 버튼을 계좌와 분리한 의미도 사라집니다.

**규칙을 어기고 싶은 충동은 규칙 트랙의 예외 조항으로 넣을 것이 아니라, 자유 트랙에서 측정되어야 할 대상입니다. 그 충동이야말로 이 제품이 보려는 것 자체입니다.**

**연 2회 제한을 두는 이유**는 선언을 희소하게 만들어 기록의 가치를 지키기 위함입니다. 아무 때나 누를 수 있으면 아무 의미가 없습니다.

**왜 필요한가 / 결산에서의 쓰임**

결산 시점에 이 기록은 **가장 강한 학습 재료**가 됩니다. 그때 적은 이유를 다시 보여주면서, 같은 기간 동안 **규칙 투자 계좌와 그냥 둔 계좌에 실제로 무슨 일이 있었는지를 나란히** 놓습니다.

그때는 세상이 끝날 것 같았는데 아무 일도 아니었다는 사실을 본인이 확인하게 되는 순간이고, 동시에 이 앱에서 가장 재미있는 장면 중 하나입니다.

**유도하는 행동**: 시장이 흔들릴 때 계좌를 뒤집는 대신 **글로 남기게** 됩니다. 행동과 기록을 분리하는 것이 이 기능의 목적입니다.

> **유지에 필요한 사람의 일: 없음.**

### 9.2 매매할 수 있는 범위 (확정)

**그 해의 종목 풀 30개 안에서만 매매할 수 있습니다. 30개 밖의 종목은 살 수 없습니다.**

| 항목 | 허용 여부 |
| --- | --- |
| 종목 풀 30개 안에서 매수 | 허용 |
| 이미 보유한 종목 추가 매수 | 허용 |
| 판 종목 다시 매수 | 허용 |
| 현금으로 보유 | 허용. **전량 현금화도 가능** |

**비용 때문만이 아닙니다.** 이 제품에서 자유 투자의 목적은 "아무거나 사보는 것"이 아니라 **"같은 재료를 두고 규칙과 내 판단 중 무엇이 나았는지 비교하는 것"** 입니다. 시작 종목과 선택 범위가 같아야 비교가 성립합니다.

온보딩에서 한 줄로 전달합니다.

> "자유 투자는 종목이 아니라 **타이밍과 비중**에서 자유롭습니다."

**현금 보유를 허용하는 이유**는, **현금으로 도망가는 것 자체가 이 제품이 관찰하려는 행동**이기 때문입니다. "무서워서 다 팔고 현금으로 뒀다"가 기록되어야 결산 때 그 판단이 옳았는지 볼 수 있습니다. **현금 비중은 화면에 표시합니다.**

### 9.3 가설 기록 (확정)

매수 시점에 아래를 입력받습니다. 이것이 이 제품의 가장 중요한 입력이며, **없으면 7장의 계산이 전부 성립하지 않습니다.**

| 항목 | 질문 | 필수 여부 |

| 논리 | 왜 지금 사는가? | 선택 |
| **되돌아볼 조건 + 그때 할 일** | 무엇이 사실로 드러나면 내 판단이 틀린 것이고, 그때 나는 무엇을 할 것인가? | **필수** |
| 목표 + 그때 할 일 | 얼마를 기대하며, 거기 닿으면 무엇을 할 것인가? | 선택 |
| 예상 보유 기간 | 언제까지 들고 있을 생각인가? | 선택 |

**필수 항목을 하나로 제한한 이유는 입력 마찰 때문입니다.** 매수 기록은 30초 안에 끝나야 하며, 나머지는 비워두고 나중에 채울 수 있어야 합니다.

가설 기록은 **매수 건마다 별도로** 남지만, **되돌아볼 조건은 가장 최근 것 하나만 그 종목 전체에 적용**됩니다. 자세한 규칙은 7.6절에 있습니다.

### 9.4 필수 항목의 입력 방식 (확정)

**조건과 대응은 별개의 두 질문이 아니라 한 문장의 빈칸 채우기로 받습니다.**

```
[ 조건 ] 하면 → [ 그때 할 일 ]

예:  [ 목표가 대비 15% 하락 ] 하면 → [ 전량 판다 ]
```

| 칸 | 입력 방식 |
| --- | --- |
| **조건 칸** | 자주 쓰이는 조건을 **선택지로 먼저 제시**하고 (예: 목표가 대비 몇 % 하락, 실적 전망 하향, 최대주주 매도 등), 원하는 사용자만 직접 서술하게 합니다 |
| **대응 칸** | **세 개 중 하나만** 고릅니다: **전량 판다 / 절반 판다 / 그대로 둔다** |

**'그대로 둔다'가 선택지에 있는 것이 중요합니다.** 조건에 닿아도 보유하겠다는 것은 회피가 아니라 **정당한 사전 계획**입니다. 다만 그 판단은 **결과를 알기 전에** 내려야 합니다.

> **기본값을 미리 채워두지 않습니다. 서비스가 기본값을 정하면 그것이 곧 권유가 됩니다.**

**왜 필요한가**: 결과를 알기 전에 판단 근거와 대응을 함께 고정시켜야 나중에 기억이 재구성되는 것을 막을 수 있습니다. **유도하는 행동**: 사기 전에 "내가 틀렸다는 걸 어떻게 알 수 있고, 그때 나는 뭘 할 것인가?"를 한 번 생각하게 됩니다.

> **유지에 필요한 사람의 일: 최초 조건 선택지 목록 작성 1회.**

### 9.5 매수 화면에서 과거의 나를 만나게 하기 (확정)

가설 기록을 작성하는 화면에서 아래를 **함께 보여줍니다.**

1. **내가 확정한 투자 수칙** 중 '매수할 때' 지정한 것
2. **이 종목에 대해 예전에 내가 쓴 기록** — 지난 가설 기록, 그때의 결과, '깨달은 것'으로 표시해 둔 문장

일지를 아무리 열심히 써도 필요한 순간에 다시 보이지 않으면 효용이 사라집니다.

> **기록은 검색해서 찾는 것이 아니라, 필요한 순간에 저절로 나타나야 합니다.**

**유도하는 행동**: "작년에도 이 종목을 이 이유로 샀다가 이렇게 됐구나"를 사기 직전에 보게 됩니다. 이 순간이 이 제품이 사용자의 행동을 실제로 바꾸는 유일한 지점입니다.

> 종목 풀이 해마다 바뀌므로 작년 종목이 올해 목록에 없을 수 있습니다. 그런 경우 이 화면에는 나타나지 않지만, 10.4절의 종목별 모아보기에서는 계속 볼 수 있습니다.

> **유지에 필요한 사람의 일: 없음.**

### 9.6 확신도와 그날의 기분 (확정)

매수 시점에 두 가지를 추가로 받습니다. **둘 다 탭 한 번으로 끝나야 합니다.**

| 항목 | 선택지 |
| --- | --- |
| 확신도 | 5단계 |
| 그날의 기분 | 조급함 / 확신 / 뒤처지는 것 같음 / 걱정 / 그냥 그럼 |

이 데이터는 '계획과 실제의 차이'와 교차되어 **개인화된 결과**로 이어집니다. 계산 비용은 사실상 0입니다.

**유도하는 행동**: 매수를 기입하기 직전에 자기 감정 상태를 인식하게 됩니다. 인식만으로도 조급한 매수의 일부가 줄어듭니다.

> **유지에 필요한 사람의 일: 없음.**

### 9.7 매도할 때 (확정)

**부분 매도와 전량 매도를 다르게 처리합니다.** 모든 매도에 회고 문항을 띄우면 30초 규칙이 무너집니다.

| 매도 종류 | 무엇을 묻는가 |
| --- | --- |
| **부분 매도** (보유 수량이 남음) | **"남은 물량에 새 조건을 세우시겠어요?"** 한 가지만. 건너뛰기 가능 |
| **전량 매도** (보유 수량 0) | 아래 회고 4문항 |

부분 매도에서 새 조건을 묻는 이유는, 7.5절의 **"새 조건이 없으면 결산일까지 보유"** 가 사용자에게 자연스럽게 전달되어야 하기 때문입니다.

**전량 매도 시 회고 (확정)**

매도를 기입하면 **그 종목의 가설 기록을 그대로 다시 띄웁니다.** 사용자는 체크만 합니다.

| # | 질문 | 답 방식 |
| --- | --- | --- |
| 1 | 처음 생각한 논리가 맞았는가? | 맞음 / 틀림 / 아직 모름 |
| 2 | 미리 정해 둔 대응대로 행동했는가? | 예 / 아니오 — 아니라면 그 이유를 선택지에서 고르기 |
| 3 | **결과가 좋았다면, 처음 생각한 논리 때문인가 다른 이유 때문인가?** | 선택 |
| 4 | 여기서 배운 것이 있다면 한 줄로 적기 | 선택 (그러나 강하게 권유) |

**3번이 핵심입니다. 맞은 이유로 벌었는지를 구분하는 것이 실력과 운을 나누는 유일한 방법입니다.**

**4번에 적은 내용은 자동으로 '깨달은 것'으로 표시되어 11장의 재료가 됩니다.**

> **유지에 필요한 사람의 일: 최초 선택지 목록 작성 1회.**

### 9.8 되돌아볼 조건 도달 알림 (확정)

가격 기반 조건은 **일 1회 종가 기준으로 확인**하고, 도달 시 알림을 보냅니다.

**문구는 반드시 과거의 사용자가 현재의 사용자에게 말을 거는 형식이어야 합니다.**

> 3월 12일에 이렇게 정하셨습니다: "목표가 대비 15% 빠지면 → 전량 판다".
> 오늘 그 선에 닿았습니다.

**알림에는 조건뿐 아니라 그때 하기로 했던 대응을 함께 보여줍니다.** 조건만 보여주면 "그래서 어쩌라고"가 되고, 대응까지 보여줘야 "내가 그때 이렇게 하기로 했었지"가 됩니다.

**알림을 받은 사용자는 세 가지 중 하나를 할 수 있고, 셋 다 정당합니다.**

| # | 선택 |
| --- | --- |
| 1 | 정해 둔 대로 실행한다 |
| 2 | 다시 살펴본 뒤 다르게 행동한다 |
| 3 | 다시 살펴본 뒤 대응 자체를 바꾸고 새 조건을 세운다 |

**2번과 3번을 택했을 때 앱은 아무런 부정적 반응을 보이지 않습니다.** 다만 그 선택은 기록되고, 결산 때 "미리 정한 것과 실제 행동이 달랐던 경우"로 집계됩니다. **그 집계가 좋다 나쁘다를 앱이 말하지 않습니다.**

이 알림 화면에서 **해당 상황에 지정한 투자 수칙**도 함께 보여줍니다. (11.5절)

**서비스가 팔라고 말하는 형식이 되면 안 됩니다.** 규제 측면에서도, 심리적 효과 측면에서도 이 구분이 결정적입니다.

> **유지에 필요한 사람의 일: 없음.** 일 1회 배치로 자동 판정·발송됩니다.

### 9.9 이번 판 예측 (재미 요소)

정기 조정일 직전과 사이클 시작 시점에 **가벼운 예측**을 하게 합니다.

- "이번 사이클, 규칙 투자와 자유 투자 중 누가 이길 것 같나요?"
- "이번 분기, 내가 계획대로 할 수 있을까요?"

**결산 때 이 예측과 실제 결과를 나란히 보여줍니다.**

**왜 필요한가**: 자기 과신을 스스로 발견하게 만드는 가장 저렴한 장치입니다.

**유도하는 행동**: 다음 이벤트를 기다리게 됩니다. 이벤트가 몇 번뿐인 이 제품의 구조적 공백을 메우는 데도 기여합니다.

> 조정일이 0회인 사용자에게는 사이클 시작 시점 예측만 제공됩니다. → 18.6

> **유지에 필요한 사람의 일: 최초 질문 문구 작성 1회.**

## 10. 투자 일지와 기록 습관

### 10.1 작성 주기 (확정)

| 주기 | 내용 | 입력 방식 |
| --- | --- | --- |
| **일간** | 오늘 기억할 만한 것 3가지 | 짧은 문장. **하나만 써도 됨** |
| **주간** | 이번 주 사건과 기억할 만한 것 3가지 | 짧은 문장 |
| **월간** | 이번 달 시장을 보고 앞으로 어떻게 할 생각인지 | 짧은 문장 |

**월간 일지에서는 자동으로 계산된 사실 수치를 보여주고 사용자가 그것을 해석하게 합니다.**

| 구분 | 보여주는 수치 |
| --- | --- |
| 시장 | 이번 달 지수 등락, 거래대금, 투자 주체별 순매수 합계 |
| 내 종목 | 내 보유 종목의 등락 |
| 내 행동 | 내가 기록한 매매 건수, 일지 작성 일수, 이번 달 수칙을 몇 번 마주쳤고 몇 번 지켰는지 |

**운영자가 매달 콘텐츠를 만드는 일은 없습니다.** 서비스는 숫자만 놓고, 해석은 사용자가 씁니다.

**왜 필요한가**: 매일 쓰면 사건이 남고, 매주 쓰면 흐름이 보이고, 매달 쓰면 자기 판단이 남습니다. **유도하는 행동**: 시장 수치를 보고 스스로 해석하는 훈련.

> **유지에 필요한 사람의 일: 없음.** 월간 수치는 전부 자동 집계입니다.

### 10.2 몰아쓰기와 소급 (확정)

| 대상 | 소급 허용 |
| --- | --- |
| 일지 작성 | **14일까지** |
| 매매 기입 | **불가** (9.1절 확정 사항) |
| '깨달은 것' 표시 | **제한 없음** |

**일지를 14일로 제한하는 이유**는, 무제한으로 열어두면 결산 직전에 한 해 치를 몰아 쓰는 일이 생기고 **그때 적히는 "그날의 기분"은 이미 결과를 알고 재구성된 것**이기 때문입니다. 이 제품이 해결하겠다고 한 문제를 제품이 스스로 만드는 셈이 됩니다.

반면 **'깨달은 것' 표시는 제한하지 않습니다.** 과거 일지를 다시 읽다가 뒤늦게 표시하는 것은 오히려 권장할 행동입니다. **작성은 제한하되 표시는 제한하지 않습니다.**

### 10.3 '깨달은 것' 표시 (확정 — 레슨 축적의 출발점)

일지를 쓸 때, 사용자는 특정 문장을 **'깨달은 것'으로 표시**할 수 있습니다. **별표를 누르는 정도의 간단한 동작**이어야 합니다.

**왜 필요한가**: 일지 전체는 양이 많아 나중에 다시 읽기 어렵지만, **표시해 둔 문장만 모으면 한 사이클에 수십 줄 정도**입니다.

**태그 (확정)**

표시할 때 어떤 종류의 교훈인지 **선택형으로 태그**를 답니다. **6개 내외로 시작합니다.**

> 사는 시점 / 파는 시점 / 종목 고르기 / 정보 판단 / 내 심리 / 시장 흐름

| 원칙 | 내용 |
| --- | --- |
| 태그를 다는 이유 | 나중에 **필요한 순간에 관련 기록만 골라 보여주기** 위해서입니다 |
| 입력 부담 | 태그 선택은 **한 번의 탭**으로 끝나야 하며, **건너뛸 수 있어야** 합니다 |

건너뛴 기록은 '분류 안 함'으로 모아 볼 수 있게 합니다.

> **유지에 필요한 사람의 일: 최초 태그 목록 확정 1회.**

### 10.4 기록 다시 보기 (확정)

**일지는 쓰는 것보다 다시 마주치는 것이 어렵습니다.** 다음 세 경로를 모두 제공합니다.

| # | 경로 | 내용 |
| --- | --- | --- |
| 1 | **종목별 모아보기** | 종목 상세에서 그 종목에 대해 내가 쓴 모든 기록을 시간순으로. **지난 사이클 기록도 포함** |
| 2 | **주제별 모아보기** | '깨달은 것' 태그별로. 예: '파는 시점'에 대해 내가 적어둔 것 모두 |
| 3 | **때맞춰 다시 보여주기** | 매수 화면, 되돌아볼 조건 도달 알림, 회고 화면에서 관련된 과거 기록을 **자동으로 함께 노출** |

**3번이 가장 중요합니다. 사용자가 일부러 찾아 들어가는 기능은 거의 쓰이지 않습니다.**

종목 풀이 해마다 바뀌므로 **주제별 모아보기(2번)가 사이클을 넘는 학습의 주된 경로**가 됩니다. 종목은 바뀌어도 "파는 시점"에 대한 자기 교훈은 그대로 쓰입니다.

> **유지에 필요한 사람의 일: 없음.**

### 10.5 기록 연속일과 스탬프 (재미 요소)

| 항목 | 내용 |
| --- | --- |
| 스탬프 | 일지를 쓸 때마다 스탬프가 찍히고, 달력 형태로 한눈에 보입니다 |
| 연속일 | 기록 연속일을 표시합니다. **끊겨도 부정적 문구를 쓰지 않고, 다시 시작한 날부터 자연스럽게 셉니다** |

**스탬프 개수로 리포트 내용을 잠그지 않습니다.** 리포트에 어떤 분석이 들어가는지는 스탬프가 아니라 **표본 수**로 결정됩니다.

| 리포트 항목 | 나타나는 조건 |
| --- | --- |
| 계획과 실제의 차이, 항목별 내역 | 항상 |
| 기분별 차이 분석 | 각 기분 구간의 매수 기록이 기준 건수 이상 |
| 반복 패턴 정리 | 회고 기록이 기준 건수 이상 |
| 사이클 간 비교 | 이전 사이클을 완주 |

기준 건수는 베타 데이터로 조정하되, **문구는 "스탬프가 부족해서"가 아니라 "기록이 n건 미만이라 아직 판단하기 이릅니다"** 로 씁니다. → 18.8

**이렇게 하는 이유 두 가지**

1. 기분 기록이 5건뿐이면 기분별 분석은 원래 의미가 없으므로 **인위적으로 잠글 필요가 없습니다.**
2. 인위적 잠금은 4.2절의 보상 설계 원칙과 마찰을 일으킵니다.

> **유지에 필요한 사람의 일: 없음.**

### 10.6 알림 우선순위 (확정)

하루 1건 제한은 확정 사항인데 알림 종류는 다섯 가지입니다. 같은 날 겹칠 때의 순서를 고정합니다.

```
1. 되돌아볼 조건 도달      ← 시의성이 가장 높음. 그날 지나면 의미 없음
2. 정기 조정일 / 결산일     ← 날짜가 정해져 있어 예측 가능
3. 주간·월간 회고          ← 주말 오전 고정
4. 일지 리마인더           ← 매일 있으므로 하루 빠져도 무방
```

- **조건 도달이 여러 종목에서 동시에 발생하면 하나로 묶어서 1건으로** 보냅니다.
- 상위 알림에 밀려 빠진 일지 리마인더는 **앱 안 배지로만** 표시합니다.

**결산일 알림은 전 사용자에게 같은 날 발송됩니다.** 사이클이 달력 연도로 통일되었기 때문이며, 이 시점에 발송량이 몰린다는 점을 감안해야 합니다.

## 11. 레슨의 축적과 투자 수칙

**이 장은 이 제품의 최종 산출물을 다룹니다.**

### 11.1 왜 필요한가

투자 일지의 가치는 쓰는 순간이 아니라 **다시 꺼내 쓰는 순간**에 발생합니다.

한 사이클 내내 성실히 기록했는데 결산 때 그 기록이 흩어진 채로 남고, 다음 사이클에 같은 실수를 반복한다면 사용자는 **"쓸 때는 좋았지만 남는 게 없다"** 고 느끼고 앱을 떠납니다.

따라서 이 서비스는 **흩어진 기록 → 정리된 레슨 → 다음 사이클의 행동 규칙**으로 이어지는 경로를 반드시 갖춰야 합니다.

**종목 풀이 해마다 바뀌므로 이 경로가 더 중요해집니다.** 다음 해에는 다른 종목을 사게 되므로, 사이클을 넘어 살아남는 것은 종목 지식이 아니라 **자기 행동에 대한 교훈**뿐입니다.

### 11.2 전체 흐름 (확정)

```
일지 작성 중 '깨달은 것' 표시 (사이클 내내, 태그 포함)
              ↓
청산 회고에서 배운 것 한 줄 기록 (매도할 때마다)
              ↓
계획과 실제의 차이, 항목별 내역, 기분별 분석 (자동 계산)
              ↓
[결산] 올해의 투자 레슨 — 종합 문서
              ↓
[결산] 투자 수칙 확정 — 사용자가 직접 3~5개 선택·편집
              ↓
[다음 사이클] 수칙이 매수·매도 화면에 다시 등장
              ↓
[다음 결산] 각 수칙을 얼마나 지켰는지, 지켰을 때 결과가 어땠는지 확인
            → 유지 · 수정 · 폐기
```

**마지막 두 단계가 이 제품을 다른 일지 앱과 구분 짓습니다.**

### 11.3 올해의 투자 레슨 (확정)

사이클 종료 시 제공하는 종합 문서입니다. **전부 자동으로 만들어지며, 운영자가 손댈 부분이 없어야 합니다.**

**포함할 내용**

| # | 항목 | 내용 |
| --- | --- | --- |
| 1 | **숫자로 본 올해** | 4개 계좌 성과, 세 개의 차이, 항목별 내역, 그리고 **'내 계획 지킨 비율'과 '규칙 실행 확인율'을 각각 별도로 제시.** 두 숫자는 원인도 처방도 다르므로 절대 합치지 않습니다. **사이클 길이(○개월)를 함께 표기합니다** |
| 2 | **내가 적어둔 것들** | '깨달은 것'으로 표시한 문장 전체를 태그별로 묶어 제시 |
| 3 | **반복된 패턴** | 자동 집계로 드러난 것들 — 어떤 기분일 때 계획과 실제의 차이가 컸는지, 어떤 종류의 종목에서 조기 매도가 잦았는지, 확신도가 높을 때와 낮을 때 결과가 어떻게 달랐는지 |
| 4 | **예측과 실제** | 사이클 중 했던 예측들과 실제 결과의 대조 |
| 5 | **비상 선언 복기** | 선언한 시점, 그때 적은 이유, 그리고 **같은 기간 동안 규칙 투자 계좌와 그냥 둔 계좌에 실제로 무슨 일이 있었는지를 나란히 제시** |
| 6 | **지난 사이클 수칙의 성적표** | 두 번째 사이클부터. 각 수칙을 몇 번 마주쳤고, 몇 번 지켰고, 지켰을 때와 안 지켰을 때 결과가 어떻게 달랐는지. **마주친 횟수가 3회 미만이면 유지·폐기 판단을 보류하도록 권유** |
| 7 | **올해 가장 잘한 판단 1개와 가장 아쉬운 판단 1개** | 후보를 자동으로 추려 제시하되 **최종 선택은 사용자가** 합니다 |

**7번을 사용자가 고르게 하는 것이 중요합니다. 앱이 대신 평가하면 훈계가 되지만, 본인이 고르면 회고가 됩니다.**

1번 항목에는 7.5절의 측정 편향 안내가 함께 들어갑니다. → 18.11

**문서의 보관**

이 문서는 **저장하고, 내보내고, 다시 볼 수 있어야** 합니다. 다음 사이클 중에도 언제든 열람 가능해야 합니다.

> **유지에 필요한 사람의 일: 없음.** → 18.7

### 11.4 투자 수칙 만들기 (확정)

레슨을 읽은 직후, 사용자는 **다음 사이클에 적용할 수칙을 확정**합니다.

**진행 방식**

| # | 단계 |
| --- | --- |
| 1 | 서비스가 **수칙 후보를 제시**합니다. 후보는 두 곳에서 나옵니다: ① 사용자가 '깨달은 것'으로 표시한 문장들 ② 자동 집계에서 드러난 패턴 |
| 2 | 사용자가 후보 중에서 고르거나, **직접 문장을 씁니다** |
| 3 | **최대 5개까지만** 확정할 수 있습니다 |
| 4 | 각 수칙에 대해 **언제 이 수칙을 다시 보여줄지**를 선택형으로 지정합니다 |

**설계 시 지켜야 할 점**

| 원칙 | 이유 |
| --- | --- |
| **후보는 제시하되 결정은 사용자가 한다** | 앱이 자동으로 수칙을 정해주면 그것은 투자 조언이 되고, 사용자 본인의 것이 아니게 되어 지켜지지도 않습니다 |
| **개수를 5개로 제한한다** | 수칙이 스무 개면 아무도 지키지 않습니다 |
| **문장은 짧고 행동 가능해야 한다** | "감정에 휘둘리지 말자"는 수칙이 아니고, "확신도 5로 산 종목은 최소 3개월 보유한다"는 수칙입니다 |
| **종목 이름이 들어간 수칙은 피한다** | 종목 풀이 해마다 바뀌므로 특정 종목에 묶인 수칙은 다음 사이클에 쓸 수 없습니다 |
| **첫 사이클 전에도 하나는 만들 수 있게 한다** | 온보딩의 연습 모드 결과를 바탕으로 **임시 수칙 1개**를 만들 수 있게 합니다 |

**수칙 문장의 좋은 예와 나쁜 예**

| 나쁜 예 | 좋은 예 |
| --- | --- |
| 감정에 휘둘리지 말자 | '조급함'을 고른 날에는 매수를 기입하지 않는다 |
| 손절을 잘하자 | '전량 판다'로 정한 조건에 닿으면 그날 안에 판단을 기록한다 |
| 공부하고 사자 | 되돌아볼 조건을 못 쓰겠으면 사지 않는다 |
| 길게 보자 | 확신도 5로 산 종목은 최소 3개월 보유한다 |

**후보 틀도 양방향이어야 합니다.** 7.9절의 항목이 양방향 대칭이므로, 수칙 후보도 한쪽만 준비하면 그 자체가 특정 방향을 권하는 것이 됩니다.

> 수칙 후보 생성 방식은 미결 사항입니다. → 18.7

### 11.5 수칙이 다시 등장하는 방식 (확정)

**확정한 수칙은 사용자가 찾아 들어가지 않아도 저절로 나타나야 합니다.**

| 시점 | 나타나는 것 |
| --- | --- |
| 사이클 시작 | 확정한 수칙 전체를 한 화면에서 확인 |
| 매수 기록 작성 시 | '매수할 때'로 지정한 수칙 |
| 매도 기록 작성 시 | '매도할 때'로 지정한 수칙 |
| 되돌아볼 조건 도달 알림 | 해당 상황에 지정한 수칙 |
| 월간 일지 작성 시 | 이번 달에 수칙을 몇 번 마주쳤고 몇 번 지켰는지 |

**표시 방식은 권유가 아니라 확인이어야 합니다.**

> "이렇게 하세요" ✕
> "작년에 이렇게 정하셨습니다" ○

**수칙을 마주쳤을 때 사용자는 지켰는지 여부만 탭으로 표시합니다.** → 18.9

> **유지에 필요한 사람의 일: 없음.**

### 11.6 수칙의 검증과 폐기 (확정)

**두 번째 사이클부터**, 각 수칙에 대해 다음을 측정해 보여줍니다.

- 이 수칙을 마주친 횟수
- 지킨 횟수와 비율
- **지켰을 때와 안 지켰을 때의 결과 차이**

그리고 사용자에게 **유지 / 수정 / 폐기**를 선택하게 합니다.

**여기서도 정직성이 중요합니다. 수칙을 지켰는데 결과가 더 나빴다면 그대로 보여주어야 합니다.** 그래야 사용자가 나쁜 수칙을 버리고 좋은 수칙만 남길 수 있습니다.

세 사이클을 지난 사용자는 자기에게 실제로 효과가 있었던 수칙 3~5개를 갖게 됩니다. **종목 풀이 해마다 바뀌어도 이것만은 남습니다.**

### 11.7 운영 비용

이 장의 기능은 대부분 **집계와 조회**로 이루어지며 운영자의 개입이 전혀 없습니다.

수칙 후보 문장을 다듬는 부분에만 문장 생성이 필요할 수 있으나, **사용자당 연 1회**이고 입력은 이미 계산된 숫자와 사용자가 직접 쓴 짧은 문장들입니다. **일지 원문 전체를 넣지 않도록 설계하면 비용은 무시할 수 있는 수준으로 유지됩니다.** → 18.7

## 12. 연습 모드

### 12.1 왜 필요한가

**이 서비스의 구조적 약점은 이벤트가 1년에 몇 번뿐이라 평소에 심심하다는 것입니다.**

**연중 가입 구조에서 이 문제는 더 커집니다.** 3차 조정일 이후에 가입한 사용자는 정기 조정을 한 번도 겪지 못한 채 결산까지 갑니다 (8.3절). 그 사용자에게 연습 모드는 유일한 이벤트입니다.

연습 모드는 이 공백을 메우는 동시에, **이 제품의 핵심 개념을 몸으로 익히게 하는 장치**입니다. "되돌아볼 조건과 그때 할 일을 미리 적어야 한다"는 말은 설명으로는 납득되지 않습니다. 한 판 해보면 납득됩니다.

그리고 **미리 준비된 과거 데이터만 쓰므로 운영 비용이 0입니다.**

### 12.2 진행 방식 (확정)

| # | 단계 |
| --- | --- |
| 1 | **종목명과 날짜를 가린** 과거 주가 흐름을 제시합니다 (선입견 제거 목적) |
| 2 | **앞으로의 흐름을 보기 전에** 목표와 되돌아볼 조건을 먼저 입력하게 합니다 |
| 3 | 주가를 하루씩 재생합니다. 사용자는 매일 **'그대로 둔다' 또는 '판다'** 중 하나만 고릅니다 |
| 4 | 끝나면 대조합니다: **미리 선언한 조건대로 했을 때의 결과 vs 실제로 누른 결과** |
| 5 | 종목과 시기를 공개합니다 |

**한 판에 3분 내외로 끝나야 합니다.**

### 12.3 설계 시 반영할 점

| # | 요구사항 | 이유 |
| --- | --- | --- |
| 1 | 미리 준비한 과거 구간 데이터를 사용합니다 | 실시간 조회나 외부 데이터가 필요 없습니다 |
| 2 | **하락 구간을 반드시 포함**시킵니다 | 계획이 손실을 줄여준 경험이 각인 효과가 훨씬 큽니다 |
| 3 | **계획대로 했을 때 오히려 손해인 구간도 넣습니다** | 그래야 사용자가 이 앱을 정직한 도구로 받아들입니다 |
| 4 | 온보딩에서 1회 체험하고, 이후에는 **언제든 다시 할 수 있는 상시 기능**으로 둡니다 | 이벤트 공백을 메웁니다 |
| 5 | 연습 모드 결과는 **실제 계좌 성과와 섞지 않고 별도로 기록**합니다 | 성과 지표가 오염되면 안 됩니다 |
| 6 | 연습 모드가 끝난 뒤에도 **'깨달은 것'을 한 줄 적을 수 있게** 합니다 | 이 기록도 결산 종합의 재료가 됩니다 |
| 7 | **연습 모드에 쓰는 종목은 그 해 종목 풀과 무관합니다** | 종목명을 가리는 것이 전제이며, 풀에 묶이면 준비 데이터가 해마다 달라져 운영 부담이 생깁니다 |

3번이 특히 중요합니다. 연습 모드가 매번 "계획대로 했으면 이겼다"로 끝나면 사용자는 이 앱이 자기를 설득하려 한다는 것을 눈치챕니다.

> **유지에 필요한 사람의 일: 최초 1회, 과거 구간 데이터 준비.** 종목 풀과 무관하므로 해마다 갱신할 필요가 없습니다.

## 13. 연간 결산과 데이터 승계

### 13.1 결산 순서 (확정)

**결산일은 전 사용자 공통이며, 그 해 12월입니다.**

| # | 단계 |
| --- | --- |
| 1 | 결산일에 두 트랙 모두 전 종목을 **확인 없이 자동으로** 매도하여 손익 확정 |
| 2 | **4개 계좌의 최종 성과와 세 개의 차이** 제시 (사이클 길이 함께 표기) |
| 3 | **사이클 회고 작성** (표준 포맷, 선택형 위주) |
| 4 | **올해의 투자 레슨 수령** (11.3절) |
| 5 | **다음 사이클의 투자 수칙 확정** (11.4절) |
| 6 | 다음 사이클 안내 — 새 종목 풀은 다음 해 1월에 공개됩니다 |

**5번을 결산의 마지막 단계로 두는 것이 중요합니다.** 회고가 끝나고 바로 다음 사이클의 약속으로 이어져야, 사용자가 다시 시작할 이유를 갖게 됩니다.

**결산과 다음 사이클 사이에는 공백이 있습니다.** 12월 결산일부터 다음 해 1월 종목 풀 공개까지 몇 주가 비며, 이 기간에는 연습 모드와 지난 기록 열람만 가능합니다. 이 공백을 어떻게 안내할지는 다이어리 은유로 설명합니다 — **"올해 다이어리는 덮었고, 내년 것은 아직 안 나왔습니다."**

### 13.2 기록이 거의 없는 사용자의 결산 (확정)

이 제품은 대부분의 계산이 자동이므로 **사용자가 앱을 열지 않아도 계좌는 굴러가고 결산도 이루어집니다.** 그런데 그 사용자에게 "당신의 계획과 실제의 차이는 −11.2%p입니다"라고 말하면, **아무것도 하지 않은 사람에게 "당신은 계획을 안 지켰다"고 말하는 셈**이 됩니다.

| 상황 | 처리 |
| --- | --- |
| 매매 기입이 0건 | 차이 지표 대신 **"이번 사이클은 기록이 없어 비교할 것이 없습니다"** 로 표시 |
| 기록이 매우 적음 | 결산은 그대로 진행하되 리포트는 **요약본**으로 |
| **사이클이 짧음 (예: 2개월 미만)** | 결산은 진행하되 **"이번 사이클은 ○개월이라 비교가 이르다"** 를 함께 표시 |
| 3개월 이상 미접속 | **알림 발송 빈도를 줄임** (비용 절감과 예의 양쪽 이유) |

세 번째 줄이 연중 가입 구조에서 새로 필요해진 항목입니다. 11월 가입자의 결산 리포트를 1월 가입자와 같은 형식으로 내보내면 안 됩니다.

### 13.3 데이터 승계 (확정)

**계좌와 보유 종목은 사이클마다 초기화됩니다. 다음 사이클로 포지션을 이월하지 않습니다.**

**그러나 아래는 사이클을 넘어 영구히 누적됩니다.**

| 승계되는 것 |
| --- |
| 일지 |
| '깨달은 것' |
| 가설 기록 (조건과 그때 할 일 포함) |
| 계획과 실제의 차이 |
| 내 계획 지킨 비율 |
| 규칙 실행 확인율 |
| 기분별 통계 |
| 비상 선언 기록 |
| 배지 |
| 연습 모드 기록 |
| 올해의 투자 레슨 |
| 투자 수칙 |

**이유 두 가지**

1. **매번 전부 초기화되면 3년 쓴 사람과 오늘 가입한 사람의 경험이 같아집니다.** 계속 쓸 이유가 사라집니다.
2. **이 제품이 궁극적으로 보여줘야 할 것은 "내 계획과 실제의 차이가 갈수록 줄고 있다"는 사실입니다.**

**종목 풀이 해마다 바뀌므로 이 원칙이 더 중요해집니다.** 종목은 이월되지 않지만 자기 행동에 대한 데이터는 그대로 쌓입니다.

**사용자에게도 이 점을 명확히 안내해야 합니다.**

> "계좌는 새로 시작하지만, 당신이 쌓은 기록과 수칙은 그대로 이어집니다."

### 13.4 사이클 재시작과 초기화 (확정)

| 기능 | 무엇을 하는가 | 제한 |
| --- | --- | --- |
| 매매 기입 정정·삭제 | 잘못 기입한 한 건을 고침 | 정정 이력을 남김. 횟수 제한 없음 |
| **사이클 재시작** | 현재 사이클의 계좌·보유 종목·가설 기록을 버리고 **종목 선택부터 다시** | **사이클당 1회, 첫 정기 조정일 이전에만** |
| 계좌 초기화 | 사이클 재시작과 같은 것으로 통합. **별도 기능으로 두지 않음** | — |
| 탈퇴 | 전체 삭제 | 삭제 전 내보내기를 한 번 권유 |

**재시작해도 종목 풀은 그대로입니다.** 그 해의 30개 목록은 연 1회 고정이므로, 재시작은 **"같은 30개 중에서 다시 고르는 것"** 을 뜻합니다. 목록 자체가 바뀌면 재시작한 사용자만 다른 재료를 갖게 되어 비교가 무너집니다.

**"첫 정기 조정일 이전에만"이라는 제한이 핵심입니다.** 그 이후에 재시작을 허용하면 **결과를 보고 되돌리는 것**이 되고, 이 제품의 모든 숫자가 무의미해집니다.

> 3차 조정일 이후 가입자는 남은 정기 조정일이 없으므로 재시작 창구도 없습니다. 이 경우의 처리는 18.6의 결정에 따릅니다.

**일지와 '깨달은 것'은 재시작해도 남깁니다.** 그것은 계좌가 아니라 기록이고, 기록의 영구 누적은 13.3절에서 확정한 원칙입니다.

| 2 | **카카오 소셜 로그인** | 가입 완료 |
| 3 | **간단한 투자 성향 설문** (적극형 / 방어형) — 3문항 이내 | 자기 성향에 대한 첫 인식 |
| 4 | **연습 모드 1판** — 온보딩의 핵심 | "왜 조건과 그때 할 일을 미리 적어야 하는가"에 대한 납득 |
| 5 | **연습 모드 결과를 바탕으로 임시 수칙 1개 만들기** | 자기 규칙을 처음 갖게 됨 |
| 6 | **이번 사이클의 남은 정기 조정일과 결산일 확인** | 언제 무슨 일이 있고 사이클이 몇 개월인지 아는 상태 |
| 7 | **종목 풀 30개 검토 및 선택** | 사이클 시작 준비 |
| 8 | **첫 가설 기록 작성** — 이때 방금 만든 수칙이 화면에 함께 나타남 | "내가 정한 규칙이 실제로 다시 나타난다"는 경험 |

### 14.2 순서를 이렇게 정한 이유

**4번을 7번보다 먼저 두는 것이 중요합니다.**

연습 모드를 먼저 겪은 사용자만이 **"왜 되돌아볼 조건을 미리 적어야 하는가"** 를 납득하고, 이후 가설 기록을 성실히 작성합니다. **설명으로는 설득되지 않습니다.**

먼저 종목을 고르게 하면 사용자는 빨리 사고 싶어지고, 그 상태에서 "조건과 그때 할 일을 적으세요"라고 하면 아무거나 골라 넘깁니다. 그러면 7장의 계산이 전부 무의미해집니다.

**5번과 8번은 가입 첫날에 "내가 정한 규칙이 실제로 다시 나타난다"는 경험을 미리 맛보게 하기 위한 것입니다.**

**6번이 특히 중요해졌습니다.** 연중 가입 구조에서는 사용자마다 남은 기간과 조정 횟수가 다릅니다. 종목을 고르기 전에 **"당신의 이번 사이클은 ○개월이고 정기 조정이 ○번 남았습니다"** 를 반드시 알려야 합니다. 이것을 모르고 시작하면 결산 때 "왜 이렇게 짧지"라는 반응이 나옵니다.

### 14.3 중간에 그만둔 사용자 (확정)

4번에서 3분, 7번에서 시간이 걸리므로 **중간 이탈은 반드시 생깁니다.**

- 각 단계 완료 시점마다 저장하고, 다시 들어오면 **그 단계부터** 이어서 진행합니다.
- 단, **7번(종목 선택)과 8번(첫 가설 기록)은 한 덩어리로 봅니다.** 종목만 고르고 가설 기록 없이 사이클이 시작되면 7장의 계산이 성립하지 않기 때문입니다.
- 7~8번 사이에서 이탈하면 **사이클은 아직 시작되지 않은 상태**로 두고, "종목 선택까지 저장되었습니다. 가설 기록을 마치면 시작됩니다"로 안내합니다.

**이탈 중에 정기 조정일이 지나가면 남은 조정 횟수가 줄어듭니다.** 다시 들어왔을 때 6번을 갱신해 다시 보여주어야 합니다.

### 14.4 투자 성향 설문의 쓰임

3문항 이내의 짧은 설문이며, 결과는 다음에만 쓰입니다.

| 쓰임 | 내용 |
| --- | --- |
| 결산 대조 | "적극형이라고 답했는데 실제 매매는 어땠는지"를 결산 리포트에서 대조 |
| 종목 풀 정렬 | 종목 풀 30개를 보여주는 순서에만 반영. **목록 자체는 전 사용자 동일** |

성향에 따라 다른 종목 풀을 주지 않습니다. 목록이 하나여야 연 1회 선정이 성립합니다.

> **유지에 필요한 사람의 일: 최초 설문 문항 작성 1회.**

## 15. 종목 풀과 정보 제공 정책

### 15.1 종목 풀 (확정)

**그 해의 종목 풀 30개는 운영자가 분석해 선정하며, 한 해 동안 모든 사용자가 같은 목록을 씁니다.**

| 항목 | 내용 |
| --- | --- |
| 개수 | 30개 |
| 선정 주체 | **운영자** |
| 선정 주기 | **연 1회** (연말~연초) |
| 적용 범위 | 그 해에 시작하는 **모든 사용자 공통** |
| 사이클 중 변경 | **없음.** 한 해 동안 목록은 고정 |

**이 목록의 성격**

> 이 목록은 **"매수를 권하는 추천 종목"이 아니라 "이번 사이클의 관찰 대상 종목"** 입니다.

앱 내 모든 문구에서 매수 권유로 읽힐 표현을 배제합니다.

| 쓰지 않는 표현 | 쓰는 표현 |
| --- | --- |
| 추천 종목, 유망 종목 | 관찰 대상 종목, 종목 풀 |
| 지금 사기 좋은 | 이번 사이클에 담긴 |
| 전문가가 고른 | 올해의 관찰 대상으로 선정된 |

**운영자 선정이 가능한 이유**

**연 1회이고, 전 사용자가 같은 목록을 쓰기 때문입니다.** 사이클이 달력 연도와 일치하므로(5.2절) 3월 가입자도 1월 가입자와 같은 30개를 봅니다. 사용자마다 사이클이 다르게 돌아가는 구조였다면 가입 시점마다 목록을 만들어야 했고, 사람이 분석하는 방식은 3.1절의 "연 단위 작업으로 한정"을 위반했을 것입니다.

**선정 시 반드시 포함해야 할 것**

| 항목 | 이유 |
| --- | --- |
| **관리종목·투자경고 종목 배제** | 7.8절의 "선정 단계에서 걸러내는 것이 최선의 대응" |
| **거래정지 위험 종목 배제** | 한 해 동안 목록을 바꾸지 않으므로 사후 대응이 어려움 |
| **최소 유동성 확보** | 30개 전부에 대해 일별 시세를 수집하고 사용자가 매매를 기입해야 함 |
| **업종 분산** | 한 업종이 무너지면 30개 전체가 무의미해짐 |

**이 선정이 만드는 리스크는 17.3절에 따로 적었습니다.** 운영자 재량이 들어가는 유일한 지점이므로, 그 대가를 문서에서 숨기지 않습니다.

> 선정 내용을 어디까지 공개할지는 미결 사항입니다. → 18.4

**유도하는 행동**: 무한한 후보 앞에서 마비되지 않고 시작하게 됩니다. 동시에 "이건 추천이 아니라 관찰 목록"이라는 프레임을 받아들이게 됩니다.

> **유지에 필요한 사람의 일: 연 1회 분석·선정 (수일).** 이것이 이 서비스에서 사람이 하는 유일한 정기 작업입니다.

### 15.2 제공하는 정보 (확정)

정보 제공의 역할을 이렇게 나눕니다.

| 구분 | 제공 주체 | 내용 |
| --- | --- | --- |
| **사실** | 서비스 (자동) | 일별 시가·종가·거래량, 공시 발생 사실과 원문 링크, 실적 발표 일정 |
| **해석** | **사용자** | 그것이 신호인지 소음인지, 내 판단을 강화하는지 반박하는지를 일지에 직접 기록 |

**공시는 MVP에 포함됩니다.** 발생 목록과 원문 링크를 전달하는 것은 **가공이 아니라 사실 전달**이므로 15.3절의 네 가지 이유 어디에도 걸리지 않고, 요약하지 않으면 저작권 문제도 생기지 않습니다.

다만 **본문을 저장하거나 요약·분류하지 않습니다.** **공시 본문을 요약하기 시작하는 순간 이 서비스는 매일 콘텐츠를 만드는 일에 발을 들이게 됩니다.**

> 공시 데이터의 이용 조건은 미결 사항입니다. → 18.2

시장 정보는 지수, 거래대금, 투자 주체별 수급 등 **공개된 사실 수치만** 자동 표시합니다. **모든 수치는 직전 영업일 종가 기준이며, 기준일을 항상 함께 표기합니다.**

1번과 4번이 결정적입니다. 연 1회 작업은 감당할 수 있고, 30개로 좁혀 주는 것은 사용자의 판단을 대신하지 않습니다. 매일 발생하는 해석은 둘 다 위반합니다.

### 15.4 신호와 소음을 배우는 방식 (확정)

사용자가 어떤 소식을 보고 "이건 신호다"라고 판단해 매매했다면, **청산 시점에 그 판단이 실제로 유효했는지를 대조해서 보여줍니다.**

1. 매수 시 가설 기록의 '논리'와 '되돌아볼 조건'에 그 판단이 남습니다
2. 전량 매도 시 회고 3번 문항에서 대조됩니다
3. 결산 때 이것들이 모여 **"내가 신호라고 생각했던 것들의 실제 적중률"** 이 됩니다

이렇게 하면 신호와 소음을 구분하는 능력이 **서비스의 큐레이션이 아니라 사용자 자신의 기록 축적으로** 길러집니다. **운영 비용은 0이고, 학습 효과는 오히려 더 큽니다.**

```
① 정해 둔 대로 실행 / ② 다르게 행동 / ③ 대응을 바꾸고 새 조건 설정
```

### 17.1 문구 형식 규칙

이 제품에서 서비스가 사용자에게 말을 거는 형식은 **두 가지뿐**입니다.

| 허용되는 형식 | 예시 |
| --- | --- |
| "당신이 예전에 이렇게 적었습니다" | "3월 12일에 이렇게 정하셨습니다: '목표가 대비 15% 빠지면 → 전량 판다'. 오늘 그 선에 닿았습니다" |
| "이런 사실이 있었습니다" | "이번 달 지수는 -3.2%, 외국인 순매수는 -1.2조원이었습니다" |

| 금지되는 형식 | 왜 |
| --- | --- |
| "지금 파는 것이 좋겠습니다" | 개인화된 매매 의견 |
| "이 종목은 지금 저평가되어 있습니다" | 투자 판단 제공 |

마지막 항목이 이번 설계에서 새로 중요해졌습니다. 종목 풀이 운영자 분석으로 선정되므로, **선정 자체보다 그것을 어떻게 말하느냐가 더 큰 리스크**가 됩니다.

| --- | --- |

| 수칙을 사용자가 직접 확정한다 | 투자 방법을 제안하지 않음 |
| 서비스가 뉴스를 해석하지 않는다 | 투자 정보 해석을 제공하지 않음 |

### 17.3 종목 풀 선정으로 남는 리스크 (명시)

**운영자가 30개를 분석해 고르는 것은 이 제품에서 재량이 개입하는 유일한 지점이며, 다음 세 가지 리스크를 남깁니다.** 이 결정의 대가이므로 문서에서 숨기지 않습니다.

| # | 리스크 | 내용 |
| --- | --- | --- |
| 1 | **투자 판단 제공으로 해석될 여지** | "왜 이 종목인가"에 답하는 순간 그 답이 투자 의견이 됩니다. 17.1절의 마지막 금지 문구가 이를 막기 위한 것입니다 |
| 2 | **성과 책임의 귀속** | 30개가 전부 부진하면 그 책임이 운영자에게 돌아옵니다. 매매 시점과 조정 기준에서 재량을 배제한 이유(8.3절)가 여기에는 적용되지 않습니다 |
| 3 | **선정 기준을 공개하기 어려움** | 정량 기준이었다면 전면 공개가 가능하지만, 분석 기반이면 공개할 것과 공개하면 곧 투자 의견이 되는 것이 섞입니다 → 18.4 |

**이 리스크를 줄이는 방향**

- 선정에서 **배제 규칙(관리종목·투자경고·저유동성)은 정량으로 명시하고 공개**합니다. 최소한 "무엇을 뺐는지"는 검증 가능해집니다
- 선정 이후에는 **개별 종목에 대한 어떤 설명도 제공하지 않습니다** (15.2절)
- 종목 풀을 **"올해의 관찰 대상"** 으로만 부르고, 유망·추천·기대 같은 단어를 쓰지 않습니다
- **'그냥 둔 계좌'가 이 리스크의 완충 장치이기도 합니다.** 30개를 그냥 들고만 있었을 때의 결과를 사용자가 늘 볼 수 있으므로, 선정의 결과가 감춰지지 않습니다

**출시 전 법률 검토가 필요한 항목입니다.**

### 18.4 종목 풀 선정 내용을 어디까지 공개할 것인가

**무엇을 결정해야 하는가**
운영자가 분석해 선정하므로 **"공개된 정량 기준"이 존재하지 않습니다.** 그러면 17장 3번의 "선정 기준을 공개합니다"를 어떻게 지킬 것인가.

**왜 중요한가**
공개하지 않으면 사용자가 검증할 수 없고, 지나치게 공개하면 그 설명이 곧 투자 의견이 됩니다 (17.3절 1번·3번).

**선택지와 장단점**

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| **배제 규칙만 공개** | "무엇을 뺐는지"는 검증 가능. 투자 의견이 되지 않음 | "왜 이 30개인지"는 여전히 불투명 |
| 선정 과정 전체 공개 (종목별 사유 포함) | 투명성 최대 | **각 사유가 곧 종목별 투자 의견**. 17장 1번 정면 위반 |
| 아무것도 공개하지 않음 | 리스크 회피 | 17장 3번을 지키지 못함. 사용자 신뢰 저하 |
| 정성 기준의 범주만 공개 | 절충 | 범주가 구체적일수록 2번에 가까워짐 |

**권장안과 근거**

**배제 규칙만 정량으로 명시해 전면 공개하고, 개별 종목의 선정 사유는 제공하지 않습니다.**

> 이번 사이클의 30개는 아래를 제외한 뒤 선정되었습니다.
> · 관리종목·투자경고 종목
> · 일평균 거래대금 ○억 미만
> · 상장 ○년 미만
> 선정된 종목에 대한 의견은 제공하지 않습니다. 판단은 직접 하십시오.

이 형태는 **"무엇을 뺐는가"만 말하고 "왜 넣었는가"는 말하지 않습니다.** 배제는 안전성 기준이므로 투자 의견이 아니지만, 편입 사유는 투자 의견입니다.

부족한 투명성은 **'그냥 둔 계좌'가 일부 보완합니다** (17.3절). 30개를 그대로 들고 있었으면 어땠는지가 늘 보이므로, 선정의 결과는 감출 수 없습니다.

**이 항목은 출시 전 법률 검토 대상입니다.**

### 18.5 연중 가입자의 시작 종목 수와 축소 경로를 어떻게 정할 것인가

**무엇을 결정해야 하는가**
결산일이 12월로 고정되고 가입은 연중 자유이므로, **가입 시점에 따라 남은 정기 조정 횟수가 3·2·1·0회로 달라집니다.** 10 → 8 → 6 → 4라는 축소 경로가 그대로는 성립하지 않습니다.

**왜 중요한가**
시작 종목 수가 정해져야 7.3절의 종목당 배분 금액이 정해지고, 8.4절의 조정 경로가 정해집니다. **이것이 정해지지 않으면 연중 가입자는 사이클을 시작할 수 없습니다.**

**선택지와 장단점**

| 선택지 | 시작 종목 수 | 최종 종목 수 | 장점 | 단점 |
| --- | --- | --- | --- | --- |
| **A. 남은 횟수에 맞춰 시작 수 조정** | 조정 3회 남으면 10개 / 2회 8개 / 1회 6개 / 0회 4개 | **항상 4개** | 최종 상태가 같아 사용자 간 비교 가능. "줄여나간다"는 경험 유지 | 늦게 가입하면 선택의 폭이 좁음 |
| **B. 항상 10개로 시작** | 항상 10개 | 4 / 6 / 8 / 10개로 제각각 | 시작 경험이 모두 같음 | 최종 종목 수가 달라 비교가 어려움. 0회 사용자는 조정을 전혀 겪지 못하면서 10개를 그대로 감 |
| **C. 남은 기간에 비례해 조정 횟수를 늘림** | 항상 10개 | 항상 4개 | 모두 같은 경험 | **매매일이 사용자마다 달라짐.** 8.3절의 공개 달력 규칙이 무너짐 |

**권장안과 근거**

**A안을 권합니다.**

1. **최종 상태가 4개로 통일**되므로 결산 시점의 비교가 성립합니다. B안은 10개로 끝난 사람과 4개로 끝난 사람을 같은 표에 놓게 됩니다.
2. **"줄여나가며 집중한다"는 경험을 짧게라도 겪게 합니다.** 이것이 규칙 투자 트랙의 학습 내용입니다.
3. C안은 매매일을 개인화해야 하므로 **8.3절의 확정 사항(공개 달력 규칙, 전 사용자 공통)을 무너뜨립니다.**

**A안 채택 시 함께 정해지는 것**

| 남은 조정 | 시작 종목 | 종목당 배분 | 축소 경로 |
| --- | --- | --- | --- |
| 3회 | 10개 | 300만 | 10→8→6→4 |
| 2회 | 8개 | 375만 | 8→6→4 |
| 1회 | 6개 | 500만 | 6→4 |
| 0회 | 4개 | 750만 | 4 (조정 없음) |

**A안의 약점**은 늦게 가입한 사용자의 선택 폭이 좁다는 것입니다. 4개만 고르는 사용자는 30개 중 26개를 포기해야 합니다. 이 문제는 18.6과 함께 다루어야 합니다.

### 18.6 정기 조정을 한 번도 겪지 못하는 사용자를 어떻게 할 것인가

**무엇을 결정해야 하는가**
3차 조정일(9월경) 이후 가입자는 **정기 조정을 한 번도 겪지 못하고 결산을 맞습니다.** 규칙 투자 트랙의 핵심 경험이 통째로 빠집니다.

**왜 중요한가**
- 규칙 투자 계좌 = 그냥 둔 계좌가 되어 **4개 계좌 중 2개가 완전히 같아집니다** (7.4절이 우려한 상황)
- '규칙 실행 확인율'의 분모가 0이 되어 계산 불가
- 12월 초 가입자는 사이클이 몇 주짜리가 됩니다
- 13.4절의 사이클 재시작 창구도 없습니다

**선택지와 장단점**

| 선택지 | 내용 | 장점 | 단점 |
| --- | --- | --- | --- |
| **A. 그대로 받되 안내** | "이번 사이클은 ○개월, 정기 조정 0회입니다"를 명시하고 시작 | 즉시 시작 가능. 유입 막지 않음 | 핵심 경험 없이 결산. 첫인상이 빈약 |
| **B. 맛보기 사이클로 명명** | A안 + **결산 리포트를 요약본으로**, 다음 사이클 예약을 강하게 권유 | 기대를 미리 낮춤. 다음 해 유입으로 연결 | 여전히 경험은 빈약 |
| **C. 다음 사이클 예약만 받음** | 종목 선택 없이 연습 모드·일지만 이용, 1월에 정식 시작 | 첫 경험이 온전함 | 최대 3~4개월 대기. 이탈 위험 |
| **D. 마지막 조정일 이후 가입자에게 축약 조정 1회 제공** | 결산 2개월 전쯤 개인별 조정 1회 | 경험 보전 | **매매일 개인화** — 8.3절 위반 |

**권장안과 근거**

**B안(맛보기 사이클)을 권합니다.**

**근거**

1. C안의 대기 3~4개월은 §12.1이 지목한 이탈 구간과 정확히 겹칩니다. 가입 시점의 의욕을 붙잡아 두어야 합니다.
2. B안에서도 **자유 투자 트랙과 투자 일지, 가설 기록은 온전히 작동합니다.** 이 제품의 핵심 산출물인 '계획과 실제의 차이'는 규칙 투자와 무관하므로, 조정이 0회여도 제품의 절반 이상은 경험됩니다.
3. D안은 매매일 개인화를 부르므로 배제합니다.

**B안 채택 시 함께 정할 것**

| 항목 | 처리 |
| --- | --- |
| 온보딩 6단계 문구 | "이번 사이클은 ○개월입니다. 정기 조정은 없고, 12월에 결산합니다" |
| 규칙 실행 확인율 | 분모가 0이므로 **미표시** ("이번 사이클에는 정기 조정이 없었습니다") |
| 규칙 투자 계좌 | 그대로 표시하되 **"그냥 둔 계좌와 같습니다"** 를 명시. 감추지 않음 |
| 결산 리포트 | 요약본 (13.2절의 "사이클이 짧음" 처리와 동일) |
| 다음 사이클 | 결산 직후 예약 권유 |

**"기간이 짧아 규칙 투자 계좌와 그냥 둔 계좌가 같습니다"라고 솔직히 말하는 것**이 7.11절 정직성 원칙과 일관됩니다. 두 계좌를 억지로 다르게 만들려 하지 않습니다.

### 18.7 투자 수칙 후보를 어떻게 만들 것인가

**무엇을 결정해야 하는가**
자동 문장 생성을 쓸지, 미리 준비한 문장 틀에 사용자의 숫자와 기록을 끼워 넣는 방식으로 할지.

**선택지와 장단점**

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| 문장 틀 방식 | 비용 0, 결과가 일정, 부적절한 문장이 나올 위험 없음 | 표현이 정형화됨 |
| 자동 문장 생성 | 사용자의 표현을 자연스럽게 반영 | 비용 발생, 품질이 일정하지 않음, 투자 조언으로 읽힐 문장 생성 위험 |
| 선택형 후보 목록만 | 가장 단순하고 비용 0 | 개인화 정도가 낮음 |

**권장안과 근거**

**문장 틀 방식을 우선 검토합니다.**

7.9절의 항목별 내역은 5종류뿐이므로, 각각에 대응하는 수칙 틀을 미리 만들어 두고 사용자의 숫자만 끼워 넣으면 됩니다. **양방향 항목이 있으므로 후보 틀도 양방향으로 준비해야 합니다.**

자동 생성을 쓴다면 **일지 원문 전체가 아니라 집계 숫자와 사용자가 표시한 짧은 문장만 입력으로 사용합니다.**

---

### 18.8 리포트 분석 항목이 나타나는 기준 건수를 몇으로 할 것인가

**무엇을 결정해야 하는가**
7.11절과 10.5절에서 쓰는 기준 건수. 초안은 3건이나 실제 데이터를 봐야 정할 수 있습니다.

**연중 가입 구조에서 더 중요해진 이유**
사이클 길이가 1~12개월로 달라지므로, **짧은 사이클 사용자는 어떤 기준을 잡아도 표본이 부족합니다.** 기준을 낮추면 3개월 사용자에게 근거 없는 결론을 주게 되고, 높이면 아무 분석도 못 받습니다.

**권장안과 근거**

**베타 기간 데이터로 조정하되, "n건 기준"과 "○개월 기준"을 함께 표기하는 원칙은 유지합니다.**

그리고 **사이클 길이가 짧은 사용자에게는 기준 건수를 낮추지 않습니다.** 낮추면 정직성 원칙(7.11절)을 위반합니다. 대신 13.2절에 따라 "이번 사이클은 ○개월이라 비교가 이르다"고 안내합니다.

---

### 18.9 수칙을 지켰는지 여부를 어떻게 확인할 것인가

**무엇을 결정해야 하는가**
가격 조건처럼 자동 판정이 가능한 수칙이 있고, 사용자만 아는 수칙도 있습니다.

**권장안과 근거**

**수칙을 마주친 시점에 사용자가 탭 한 번으로 표시하는 방식을 기본으로 하고, 자동 판정이 가능한 유형만 부가적으로 자동 기록합니다.**

수칙은 사용자가 자기 언어로 쓴 문장이므로 대부분 자동 판정이 불가능합니다. 자동화를 전제로 설계하면 수칙 작성 자체를 구조화된 형식으로 제한해야 하고, 그러면 11.4절의 "짧고 행동 가능한 자기 문장"이라는 성격이 사라집니다.

표시가 누락된 경우 **"마주친 횟수 중 표시된 것만"** 으로 계산하고 그 사실을 명시합니다.

---

### 18.10 규칙 투자의 조정 로직을 MVP에서 유지할 것인가

**무엇을 결정해야 하는가**
"열위 종목 매도 후 잔여 종목에 분산"은 검증된 전략이 아닙니다.

**권장안과 근거**

**MVP에서는 유지하되 예시 규칙임을 명시하고 '그냥 둔 계좌'를 나란히 표시합니다.**

이 트랙의 목적은 수익이 아니라 **비교 기준선**입니다. 그리고 '그냥 둔 계좌'를 나란히 보여주기 때문에, 이 규칙이 나빴다면 사용자가 직접 확인하게 됩니다.

다른 규칙으로 바꾸는 것은 오히려 위험합니다. **어떤 규칙을 고르든 그 선택 자체가 운영자의 투자 판단**이 되고, 종목 선정에 이어 재량이 하나 더 늘어납니다. 17.3절의 리스크를 키우는 방향입니다.

---

### 18.11 자기 보고 조건 때문에 생기는 측정 편향을 어떻게 다룰 것인가

**무엇을 결정해야 하는가**
가격으로 판정할 수 없는 조건은 **사용자가 도달을 표시해야만** '내 계획대로 계좌'에 반영됩니다. 표시하지 않으면 **계획과 실제의 차이가 실제보다 작게 나옵니다.**

**왜 중요한가**
그 숫자가 체계적으로 작게 나오면, 사용자는 "나는 생각보다 계획을 잘 지키는 사람"이라는 틀린 결론을 얻게 됩니다. 이 제품이 하려던 일과 정반대입니다.

**선택지와 장단점**

| 선택지 | 장점 | 단점 |
| --- | --- | --- |
| 편향을 리포트에 함께 표시 | 정직하고 비용 0 | 숫자가 하나 늘어 복잡해짐 |
| 자기 보고 조건을 아예 받지 않음 | 편향 없음 | 사고 폭이 크게 줄어듦 |
| 미표시 조건을 추정으로 보정 | 숫자가 정확해 보임 | **서비스가 사용자가 하지 않은 판단을 대신 내리는 것.** 7.5절 위배 |
| 월간 일지에서 미표시 조건을 한 번 물어봄 | 누락을 줄임 | 완전히 없애지는 못함 |

**권장안과 근거**

**자동 판정 조건과 자기 보고 조건의 비중을 리포트에 함께 표시하고, 자기 보고 비중이 높으면 "이 숫자는 실제보다 작게 나왔을 수 있다"고 명시합니다.**

세 번째 선택지는 반드시 배제합니다. 7.5절의 기본 원칙과 17장 1번을 동시에 위반합니다.

네 번째는 첫 번째와 함께 채택할 수 있습니다.

---

### 18.12 카카오 로그인만으로 갈 것인가

**무엇을 결정해야 하는가**
카카오 계정이 없으면 가입할 수 없고, 계정을 잃으면 복구 경로가 없습니다.

**왜 중요한가**
**계정 분실 문의는 1인 운영에서 감당하기 어려운 유형입니다.** 이 제품은 데이터가 쌓일수록 가치가 커지는 구조이므로, 여러 사이클 치 기록을 잃은 사용자의 문의는 특히 무겁습니다.

**권장안과 근거**

**MVP는 카카오 단일로 가되, 이메일 백업 수단을 넣는 비용과 계정 복구 문의를 감당하는 비용을 비교해 결정합니다.**

부족한 부분은 **데이터 내보내기(13.5절)를 눈에 띄게 두는 것으로 일부 보완합니다.** 특히 **결산 직후가 내보내기를 권할 최적의 시점**입니다. 사용자가 자기 기록의 가치를 가장 크게 느끼는 순간이기 때문입니다.

---

### 18.13 실제 투자 전환 기능을 어느 수준까지 제공할 것인가

**무엇을 결정해야 하는가**
증권사 연동과 자동 주문은 기술적·법적 장벽이 크고 1~3인이 감당하기 어렵습니다.

**권장안과 근거**

**MVP에서는 내가 기입한 매매 내역을 목록으로 보여주는 것까지만 합니다. 데이터 구조는 추후 연동이 가능하도록 설계합니다.**

이 제품은 애초에 앱 안에서 매매하지 않는 구조(8.5절)이므로, 사용자는 이미 자기 증권사에서 실행하거나 실행하지 않고 앱에는 기록만 남기고 있습니다.

목록 제공 시 17장 7번에 따라 "실제 투자로의 전환은 사용자의 판단과 책임"임을 함께 표시합니다.

---

### 18.14 외부 전문가 로직 판매를 어떻게 다룰 것인가

**무엇을 결정해야 하는가**
특정인의 매매 로직을 인앱결제로 판매하는 것은 **투자자문업 해당 여부 검토가 필요합니다.**

**권장안과 근거**

**MVP에서 제외합니다. 이 문서에는 실명을 쓰지 않고 "외부 전문가 로직"으로만 기술합니다.**

**종목 선정에 이미 운영자 재량이 들어갔으므로(17.3절), 여기에 외부 전문가 로직까지 더하면 재량의 총량이 두 배가 됩니다.** 규제 리스크는 단순히 더해지는 것이 아니라 서로 강화됩니다. 최소한 종목 선정의 법률 검토가 끝난 뒤에 다시 볼 항목입니다.

## 19. 향후 확장 시 구조적으로 대비할 사항

### 19.1 복수의 규칙 세트 지원

**지금 구현하지 않는 이유**
규칙 투자 로직이 하나뿐이어도 4개 계좌 비교라는 핵심 경험은 완결됩니다. 그리고 종목 선정에 이미 재량이 들어갔으므로 규칙까지 여러 개로 늘리면 리스크가 겹칩니다 (18.14).

**미리 고려할 것**
**규칙은 데이터로 표현되어야 하며 코드에 고정되면 안 됩니다.** 규칙이 담아야 할 요소:

- 30개 중 몇 개를 어떤 기준으로 고를 것인가
- 정기 조정을 몇 번, 어떤 달력 규칙으로 산출할 것인가
- 각 조정일에 무엇을 팔고 어떻게 재분배할 것인가

**어떤 규칙을 쓰더라도 12월 결산일 전량 매도 원칙은 동일합니다.**

**다만 사이클은 언제나 하나입니다.** 여러 규칙을 비교한다는 것은 **한 사이클 안에 규칙 계좌가 여럿 있다는 뜻**이지, 사용자가 두 개의 사이클을 동시에 굴린다는 뜻이 아닙니다.

### 19.2 투자 수칙의 확장

**지금 구현하지 않는 이유**
수칙의 장기 성적은 두 번째 사이클이 끝나야 의미가 생깁니다.

**미리 고려할 것**
수칙 하나가 가져야 할 정보:

- 문장 / 언제 보여줄지 / 어느 사이클에서 만들어졌는가
- 사이클별로 몇 번 마주쳤고 몇 번 지켰는가
- 유지·수정·폐기 이력 (수정된 경우 이전 문장과의 연결)

**종목 풀이 해마다 바뀌므로 수칙은 종목에 묶이지 않아야 합니다** (11.4절). 데이터 구조에서도 수칙과 종목을 연결하지 않습니다.

### 19.3 실제 투자 전환

**지금 구현하지 않는 이유**
증권사 연동과 자동 주문은 기술적·법적 장벽이 크고 1~3인이 감당하기 어렵습니다 (18.13).

**미리 고려할 것**
매매 한 건이 **"사용자가 직접 기입한 것"인지 "외부에서 자동으로 들어온 것"인지 구분**될 수 있어야 하고, 두 경로가 섞여도 계좌 계산이 일관되게 유지되어야 합니다.

### 19.4 뉴스 자동 수집과 분류

**지금 구현하지 않는 이유**
사람이 하면 매일 발생하는 고정 인건비가 되고, 이 서비스가 가장 먼저 무너질 지점입니다 (15.3).

**미리 고려할 것**
향후 뉴스 수집과 자동 태깅, **공시 본문의 요약**을 도입하더라도 **사람이 개입하지 않는 방식이어야 합니다.**

**공시 발생 목록과 원문 링크는 이미 MVP에 포함되므로 여기서 제외합니다.**

도입하더라도 **해석은 여전히 사용자가 해야 합니다.** 자동 분류의 역할은 "이 소식이 있었다"를 놓치지 않게 하는 것까지입니다.

### 19.5 종목 풀 선정의 자동화

**지금 구현하지 않는 이유**
연 1회 작업이므로 사람이 해도 3.1절의 제약을 만족합니다. 그리고 정량 기준만으로 30개를 뽑으면 종목의 질을 담보하기 어렵다는 판단에서 운영자 분석을 선택했습니다.

**미리 고려할 것**
17.3절의 리스크 세 가지 중 어느 하나라도 현실화되면 **정량 기준 기계 선정으로 전환할 수 있어야 합니다.** 그러려면:

- 배제 규칙은 이미 정량으로 명시되어 있으므로(18.4) 그대로 재사용 가능
- 편입 기준을 정량으로 표현할 자리를 데이터 구조에 남겨 둡니다
- **전환하더라도 "연 1회, 전 사용자 공통"이라는 구조는 그대로 유지됩니다.** 사이클이 달력 연도로 고정되어 있으므로 선정 주체만 바꾸면 됩니다

이 전환 가능성을 열어 두는 것이 종목 선정 재량에 대한 가장 현실적인 보험입니다.

### 19.6 구독 및 결제

**지금 구현하지 않는 이유**
베타 출시이며, 무엇이 유료 가치가 있는지는 데이터가 쌓여야 알 수 있습니다.

**미리 고려할 것**
**무료 구간은 기록 무제한으로 두고, 유료 구간은 누적 데이터 기반 심화 리포트와 수칙 분석으로 설계하는 방향**입니다.

기록 자체에는 절대 과금하지 않습니다. **기록이 쌓인 사용자일수록 가치가 커지는 구조**이므로, 가입 직후가 아니라 **몇 사이클 뒤에 전환을 유도**합니다.

### 19.7 여러 해에 걸친 비교 리포트

**지금 구현하지 않는 이유**
비교할 사이클이 없습니다.

**미리 고려할 것**
**계획과 실제의 차이가 해마다 어떻게 변했는지**를 보여주는 리포트입니다. **이 차이가 줄어드는 것이 이 제품의 가치를 증명하는 유일한 증거**입니다.

사이클별 집계값이 동일한 기준으로 저장되어야 하며, **계산 방식이 바뀔 경우 과거 데이터를 새 기준으로 다시 계산할 수 있어야** 합니다.

함께 저장해야 할 것:

| 항목 | 이유 |
| --- | --- |
| 측정 편향 비중 (18.11) | 자기 보고 비중이 다르면 "차이가 줄었다"가 실제 개선인지 측정 누락인지 구분 불가 |
| **사이클 길이** | 첫 사이클이 3개월, 다음이 12개월이면 그대로 비교할 수 없음 |
| **그 해의 종목 풀** | 종목이 매년 다르므로 시장 환경 차이를 보정해서 읽어야 함 |

**첫 사이클이 짧은 사용자가 많다는 점을 전제해야 합니다.** 연중 가입이 허용되므로 대부분의 사용자에게 첫 사이클은 12개월이 아닙니다. 두 번째 사이클부터가 온전한 비교의 시작점입니다.
