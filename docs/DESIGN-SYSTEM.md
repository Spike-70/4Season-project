## 1. 디자인 원칙

PRD 1.6은 이 제품을 "투자 정보 앱이 아니라 기록 앱"으로 규정한다. 시각 설계도 그 규정을 따른다.

| # | 원칙 | 구체적 귀결 |
| --- | --- | --- |
| 1 | **수치는 담백하게** | 큰 숫자를 크게 키우지 않는다. 수익률 표시에 그라데이션·글로우·애니메이션 카운트업을 쓰지 않는다 (PRD 4.1) |
| 2 | **재미는 기록에만 붙인다** | 스탬프·배지·연속일에는 시각적 즐거움을 허용하되, 매매 기입·수익률 화면에는 축하 연출을 일절 두지 않는다 (PRD 4.2) |
| 3 | **양방향 대칭을 시각으로 보장한다** | 항목별 내역과 배지는 항상 짝이 나란히 놓이며, 한쪽만 강조하는 색·크기·순서를 쓰지 않는다 (PRD 7.9) |
| 4 | **기준일을 숨기지 않는다** | 성과 수치가 있는 모든 곳에 기준일 캡션이 붙는다. 작게 쓰되 지우지 않는다 (PRD 7.9) |
| 5 | **입력은 탭 몇 번으로 끝난다** | 선택형을 기본 형태로, 자유 입력을 보조 형태로 둔다. 필수 표시는 실제 필수 항목에만 (PRD 4.3) |
| 6 | **과거 기록이 스스로 나타난다** | `RecallBlock`은 부가 정보가 아니라 화면의 1급 구성요소다. 접힘 상태를 기본값으로 두지 않는다 (PRD 9.5, 10.4) |
| 7 | **모바일이 기준이다** | 데스크톱은 모바일 레이아웃의 확장이며, 그 반대가 아니다 (PRD 6.1-20) |
| 8 | **서비스는 권유하지 않는다** | 버튼 문구·강조 색·기본 선택값이 특정 행동을 유도하지 않는다. '그대로 둔다'는 '전량 판다'와 시각적으로 동등하다 (PRD 9.4, 17.1) |

## 2. 토큰 체계 개요

토큰은 3계층으로 구성한다. **컴포넌트는 시맨틱 토큰만 참조하고 원시 토큰을 직접 쓰지 않는다.**

| 계층 | 예 | 정의 위치 | 사용처 |
| --- | --- | --- | --- |
| **원시(Primitive)** | `slate-700`, `crimson-500` | Tailwind `theme.colors` | 시맨틱 토큰 정의에만 |
| **시맨틱(Semantic)** | `--color-surface`, `--color-text-primary` | CSS 변수 (`:root`) | Tailwind 확장 색상으로 노출 |
| **컴포넌트(Component)** | `--btn-primary-bg` | 컴포넌트 CSS 변수 | 해당 컴포넌트 내부 |

**CSS 변수를 쓰는 이유**: 테마 전환(라이트/다크)과 손익 색상 반전 설정을 클래스 교체 없이 처리하기 위해서다. Tailwind 클래스명은 고정되고 값만 바뀐다.

**명명 규약**: `--{category}-{role}-{variant}-{state}`

| 예 | 의미 |
| --- | --- |
| `--color-text-primary` | 본문 기본 텍스트 |
| `--color-bg-surface-raised` | 한 단계 올라온 표면 |
| `--color-accent-profit` | 이익 방향 색 |
| `--space-gutter-mobile` | 모바일 좌우 여백 |

## 3. 색상

### 3.1 팔레트 설계 의도

기록 앱의 정체성에 맞춰 **채도가 낮은 잉크 계열**을 기본으로 하고, 강조색은 종이 위 형광펜 정도의 존재감으로 제한한다. 브랜드 색이 화면을 지배하면 숫자가 극적으로 보이며, 이는 원칙 1과 충돌한다.

### 3.2 원시 색상

| 그룹 | 용도 | 단계 |
| --- | --- | --- |
| `ink` | 텍스트·배경 기본. 중성 회색에 약간의 청색 편향 | 50, 100, 200, 300, 400, 500, 600, 700, 800, 900, 950 |
| `paper` | 표면. 따뜻한 미색 계열 | 0(순백), 50, 100, 200 |
| `brand` | 서비스 강조. 절제된 인디고 | 50, 100, 300, 500, 600, 700 |
| `crimson` | 상승·이익 (국내 관례) | 50, 100, 400, 500, 600, 700 |
| `azure` | 하락·손실 (국내 관례) | 50, 100, 400, 500, 600, 700 |
| `amber` | 주의·대기 | 50, 100, 400, 500, 600 |
| `moss` | 완료·긍정 상태 (수익과 무관한 맥락) | 50, 100, 400, 500, 600 |

> **`moss`를 별도로 두는 이유**: 초록을 수익 색으로 쓰지 않기 때문이다. 국내 사용자에게 상승은 빨강이며, 초록을 "좋음"으로 쓰면 손익 색과 상태 색이 충돌한다. `moss`는 '기록 완료', '수칙 지킴' 등 **수익률과 무관한 긍정 상태**에만 쓴다.

### 3.4 손익 색상 정책

| 항목 | 규칙 |
| --- | --- |
| 기본 매핑 | 상승·이익 = `--color-profit`(적), 하락·손실 = `--color-loss`(청) |
| 사용자 설정 | 설정에서 반전 가능 (해외 관례 사용자 대응). CSS 변수만 교체하며 컴포넌트는 변경 없음 |
| 색 단독 사용 금지 | 부호(`+`/`−`)와 방향 아이콘을 항상 함께 표시한다 (§18 접근성) |
| 0 처리 | `--color-neutral-value`. 0을 이익 색으로 칠하지 않는다 |
| **계좌 간 차이** | 차이 값(`gap`)에도 같은 매핑을 적용한다. 단 **'계획과 실제의 차이'가 음수인 경우에도 시각적 경고를 추가하지 않는다** — PRD 7.11-1의 정직성 요구이며, 나쁜 결과에 경고색을 얹으면 훈계가 된다 |

### 3.5 계좌 식별 색상

4개 계좌는 차트와 범례에서 항상 같은 색을 쓴다. **명도와 채도가 서로 다르게** 배정하여 색맹 사용자도 구분할 수 있게 한다.

| 계좌 | 토큰 | 시각 특성 | 선 스타일 |
| --- | --- | --- | --- |
| 규칙 투자 | `--color-account-rule` | 중간 명도 보라 | 실선 |
| 자유 투자 | `--color-account-free` | 고채도 인디고 (가장 굵게) | 실선, 2px |
| 내 계획대로 | `--color-account-plan` | 인디고 계열 저채도 | 파선 |
| 그냥 둔 | `--color-account-hold` | 무채색 회색 | 점선 |

> '그냥 둔 계좌'를 무채색으로 두는 것은 **기준 바닥선**이라는 의미를 시각으로 전달하기 위해서다 (PRD 7.2). '내 계획대로 계좌'를 자유 투자와 같은 색조의 파선으로 두어 **짝 관계**를 드러낸다.

## 4. 타이포그래피

### 4.1 폰트

| 용도 | 폰트 | 근거 |
| --- | --- | --- |
| 본문·UI | Pretendard Variable | 한글 가독성, 가변 폰트로 파일 1개 |
| 숫자 | Pretendard Variable + `font-variant-numeric: tabular-nums` | 표에서 자릿수 정렬. 별도 숫자 폰트를 쓰지 않는다 |
| 대체 | system-ui, -apple-system, sans-serif | |

**로딩 전략**: `woff2` 서브셋(한글 KS X 1001 + Latin + 숫자·기호)을 `font-display: swap`으로 로드한다. 가변 폰트 1개만 쓰므로 굵기별 추가 요청이 없다.

### 4.2 타입 스케일

모바일 기준값이며 데스크톱에서 일부만 확대한다.

| 토큰 | 크기/행간 | 굵기 | 자간 | 용도 |
| --- | --- | --- | --- | --- |
| `display` | 32/40 | 700 | -0.02em | 결산 리포트 표지, 온보딩 히어로 |
| `title-1` | 24/32 | 700 | -0.01em | 화면 제목 |
| `title-2` | 20/28 | 600 | -0.01em | 섹션 제목 |
| `title-3` | 17/24 | 600 | 0 | 카드 제목 |
| `body-1` | 16/26 | 400 | 0 | 본문 기본 |
| `body-2` | 14/22 | 400 | 0 | 보조 본문 |
| `label` | 14/20 | 500 | 0 | 폼 라벨, 버튼 |
| `caption` | 12/18 | 400 | 0 | 기준일, 메타 정보 |
| `overline` | 11/16 | 600 | 0.06em | 카테고리 태그 |
| `numeral-lg` | 28/36 | 700 | -0.02em | 주요 수치 (계좌 총액) |
| `numeral-md` | 20/28 | 600 | -0.01em | 보조 수치 |
| `numeral-sm` | 15/22 | 600 | 0 | 표 안 수치 |

> **`display`를 수치에 쓰지 않는다.** 32px 숫자는 그 자체로 극적이며 PRD 4.1의 "숫자는 담백하게"와 충돌한다. 가장 큰 수치 스타일은 `numeral-lg`(28px)로 상한을 둔다.

### 4.3 텍스트 규칙

| 항목 | 규칙 |
| --- | --- |
| 최대 줄 길이 | 본문 40~45자(한글). `max-w-prose` 대신 전용 토큰 `--measure-body` 사용 |
| 줄바꿈 | `word-break: keep-all` — 한글 단어 중간 분리 방지 |
| 말줄임 | 목록 항목은 2줄 클램프. 일지 본문은 클램프하지 않는다 |
| 대문자 변환 | 사용하지 않는다 (한글에 무의미) |

## 5. 간격·크기·반경·그림자

### 5.1 간격 스케일

4px 배수. Tailwind 기본 스케일을 그대로 쓰되 시맨틱 별칭을 추가한다.

| 별칭 | 값 | 용도 |
| --- | --- | --- |
| `--space-gutter` | 16px (모바일) / 24px (≥md) | 화면 좌우 여백 |
| `--space-section` | 32px | 섹션 간 |
| `--space-card` | 16px | 카드 내부 패딩 |
| `--space-card-lg` | 20px | 주요 카드 |
| `--space-stack-sm` | 8px | 밀접 요소 간 |
| `--space-stack-md` | 12px | 일반 요소 간 |
| `--space-inline` | 8px | 인라인 요소 간 |

### 5.2 터치 타깃

| 항목 | 최소 크기 |
| --- | --- |
| 모든 인터랙티브 요소 | 44 × 44px |
| 선택형 칩 | 높이 40px, 좌우 패딩 14px, 터치 영역은 패딩으로 44px 확보 |
| 아이콘 버튼 | 44 × 44px (아이콘 24px + 패딩) |
| 인접 타깃 간 최소 간격 | 8px |

### 5.3 모서리 반경

| 토큰 | 값 | 용도 |
| --- | --- | --- |
| `--radius-sm` | 6px | 태그, 배지 |
| `--radius-md` | 10px | 버튼, 입력 필드 |
| `--radius-lg` | 14px | 카드 |
| `--radius-xl` | 20px | 바텀시트, 모달 |
| `--radius-full` | 9999px | 칩, 아바타 |

### 5.4 그림자

기록 앱의 종이 질감에 맞춰 **그림자를 최소화**하고 경계선으로 층위를 표현한다.

| 토큰 | 값 | 용도 |
| --- | --- | --- |
| `--shadow-none` | none | 기본 카드 (경계선으로 구분) |
| `--shadow-sm` | `0 1px 2px rgba(0,0,0,0.04)` | 살짝 떠 있는 카드 |
| `--shadow-md` | `0 4px 12px rgba(0,0,0,0.08)` | 드롭다운, 팝오버 |
| `--shadow-lg` | `0 12px 32px rgba(0,0,0,0.12)` | 바텀시트, 모달 |

다크 모드에서는 그림자 대신 `--color-border-strong`을 사용한다.

### 5.5 z-index

| 토큰 | 값 | 용도 |
| --- | --- | --- |
| `--z-base` | 0 | |

| 대상 | 허용 |
| --- | --- |

`prefers-reduced-motion: reduce`에서 모든 트랜지션을 `--duration-instant`로 축소하고, 위치 이동 애니메이션을 페이드로 대체한다.

## 9. 숫자와 데이터 표기 규칙

이 절은 **화면 설계가 아니라 데이터 계약**이다. PRD 7.9의 표시 단위 규칙을 컴포넌트 수준에서 강제한다.

### 9.1 수치 표기

| 대상 | 형식 | 예 |
| --- | --- | --- |
| 수익률·차이 | 퍼센트포인트 소수 1자리 + 부호 | `+14.2%p` |
| 금액 병기 | 괄호 안, 천 단위 구분 | `+14.2%p (1,420,000포인트)` |
| 계좌 총액 | 천 단위 구분 + `포인트` | `31,240,000포인트` |
| 주가 | 천 단위 구분 + `원` | `72,300원` |
| 수량 | 소수점 이하 유효 자릿수만 | `120주`, `120.5주` |
| 비율 (준수율) | `n회 중 m회` + 괄호 백분율 | `7회 중 4회 (57%)` |
| 기간 | `○개월` | `9.5개월` |
| 날짜 | `M월 D일` (같은 해) / `YYYY. M. D.` (다른 해) | `8월 3일` |

### 9.2 필수 동반 표기

| 수치 | 반드시 함께 표시할 것 |
| --- | --- |
| 모든 성과 수치 | 기준일 캡션 (`8월 3일 종가 기준`) |
| 사이클 성과 | 사이클 길이 (`9.5개월 기준`) |
| 모든 비율 | 분모 (`7회 중`) |
| 항목별 내역 | 건수 (`4건 기준`) |
| 기준 미달 항목 | `아직 판단하기 이릅니다` 문구, 수치는 표시하되 해석 문장 제거 |

이 규칙은 `<MetricValue>`, `<RateMetricValue>` 컴포넌트가 **구조적으로 강제**한다. 기준일 prop이 없으면 타입 오류가 난다 (§11.9).

### 9.3 반올림

| 항목 | 규칙 |
| --- | --- |
| 표시 반올림 | 소수 1자리 (`toFixed(1)`) |
| 계산 | 서버 `NUMERIC` 원값. 클라이언트에서 재계산하지 않는다 |
| 0 근처 | `-0.0%p` 표기 금지. 절댓값 0.05 미만은 `0.0%p`, 중립색 |

## 11. 기본 컴포넌트 명세

각 컴포넌트는 변형(variant), 크기(size), 상태(state)를 조합한다. 상태는 `default / hover / active / focus-visible / disabled / loading`을 공통으로 가진다.

### 11.1 Button

| 속성 | 값 |
| --- | --- |
| variant | `primary`, `secondary`, `ghost`, `danger`, `neutral` |
| size | `sm`(36px), `md`(44px), `lg`(52px) |
| 폭 | `auto`, `full` |
| 부가 | `leadingIcon`, `trailingIcon`, `isLoading` |

| variant | 배경 / 텍스트 / 테두리 | 용도 |
| --- | --- | --- |
| `primary` | `--color-accent-primary` / inverse / none | 화면당 최대 1개 |
| `secondary` | surface / accent / `--color-border-strong` | 보조 액션 |
| `ghost` | 투명 / secondary / none | 취소, 건너뛰기 |
| `danger` | 투명 / `--color-status-danger` / danger | 삭제, 탈퇴, 재시작 |
| `neutral` | `--color-bg-muted` / primary / none | **선택지가 동등할 때** |

> **`neutral` variant가 이 제품에 필수적이다.** '전량 판다 / 절반 판다 / 그대로 둔다'를 `primary` + `secondary`로 구성하면 그 순간 서비스가 특정 대응을 권하게 된다 (PRD 9.4). 동등 선택지는 전부 `neutral`을 쓰고 선택된 것만 강조한다.

**로딩 상태**: 텍스트를 유지한 채 스피너를 왼쪽에 추가하고 `aria-busy="true"`. 버튼 폭이 변하지 않아야 한다.

### 11.2 Chip / ChipGroup

선택형 입력의 기본 형태. PRD 4.3의 "선택형 우선"을 담당하는 핵심 컴포넌트다.

| 속성 | 값 |
| --- | --- |
| variant | `choice`(단일 선택), `multi`(복수), `filter`, `static` |
| size | `sm`(32px), `md`(40px) |
| 상태 | `unselected`, `selected`, `disabled` |

**선택 상태 표현**: 배경 `--color-accent-subtle` + 테두리 `--color-accent-primary` + 텍스트 `--color-accent-primary`. **체크 아이콘을 함께 표시**하여 색만으로 구분하지 않게 한다.

**ChipGroup**: 가로 스크롤(`overflow-x-auto` + 스냅) 또는 줄바꿈(`flex-wrap`). 기본은 줄바꿈이며, 8개 초과 시 가로 스크롤.

> ChipGroup에는 **기본 선택값을 두지 않는다** (`defaultValue` prop 없음). PRD 9.4의 "서비스가 기본값을 정하면 그것이 곧 권유가 됩니다"를 API 수준에서 막는다.

### 11.3 Input / Textarea / NumberInput

| 속성 | 값 |
| --- | --- |
| 높이 | Input 48px, Textarea 최소 88px |
| 배경 | `--color-bg-surface-sunken` |
| 테두리 | `--color-border-default`, 포커스 시 `--color-border-focus` 2px |
| 라벨 | 상단 배치, `label` 스타일. placeholder를 라벨 대용으로 쓰지 않는다 |
| 도움말 | 하단 `caption`, `--color-text-tertiary` |
| 오류 | 하단 `caption`, `--color-status-danger` + 테두리 색 변경 + `aria-invalid` |
| 글자 수 | 상한이 있는 필드만 우하단에 표시 |

**NumberInput**: `inputMode="decimal"`, 천 단위 구분 자동 삽입, 포커스 시 원값 표시. 증감 스테퍼는 두지 않는다(오입력 유발).

**Textarea**: 자동 높이 확장. 일지·회고에 사용하며 최대 높이 제한 후 내부 스크롤.

### 11.4 Card

| 속성 | 값 |
| --- | --- |
| variant | `plain`(테두리만), `raised`(그림자), `subtle`(배경 강조), `interactive`(탭 가능) |
| padding | `sm`(12px), `md`(16px), `lg`(20px) |
| 구성 | `Card.Header`, `Card.Body`, `Card.Footer` |

`interactive` 카드는 전체가 하나의 터치 타깃이며 내부에 별도 버튼을 두지 않는다(중첩 인터랙션 금지).

### 11.5 Sheet (바텀시트)

모바일의 주요 모달 형태. 매매 기입, 가설 작성, 회고, 조건 재설정에 사용한다.

| 속성 | 값 |
| --- | --- |
| 높이 | `auto`, `half`, `full` |
| 핸들 | 상단 드래그 핸들 표시 |
| 닫기 | 배경 탭, 아래로 드래그, 닫기 버튼 |
| 스크롤 | 내부 스크롤. 헤더·푸터 고정 |
| 포커스 | 열릴 때 첫 포커서블로 이동, 닫을 때 트리거로 복귀 |

**≥md에서는 중앙 모달로 전환**한다. 동일 컴포넌트가 뷰포트에 따라 표현을 바꾼다.

**임시 저장**: 시트를 닫아도 입력값을 폼 상태에 보존한다. PRD 4.3의 "빈칸 허용, 나중에 채울 수 있어야"를 구현하려면 실수로 닫혔을 때 내용이 사라지면 안 된다.

### 11.6 Modal

파괴적 확인(재시작, 탈퇴, 매매 삭제)에만 사용한다. 정보 전달용 모달은 두지 않는다.

| 구성 | 제목 / 본문 / 액션 2개 |
| --- | --- |
| 액션 배치 | 취소(ghost) 왼쪽, 확인(danger) 오른쪽 |
| 기본 포커스 | 취소 |

### 11.7 Toast

| 속성 | 값 |
| --- | --- |
| variant | `info`, `success`, `error` |
| 지속 | 3초 (error는 5초) |
| 위치 | 하단, 탭바 위 |
| 액션 | 최대 1개 (`실행 취소` 등) |
| 동시 표시 | 1개. 새 토스트가 기존 것을 대체 |

**축하 토스트를 만들지 않는다.** 성공 토스트 문구는 "저장했습니다" 수준의 사실 진술로 제한한다 (PRD 4.1).

### 11.8 NoticeBanner

API `meta.notice`를 렌더링하는 전용 컴포넌트.

| 속성 | 값 |
| --- | --- |
| severity | `INFO`(회색 배경), `IMPORTANT`(amber 배경) |
| 배치 | 관련 콘텐츠 바로 아래 |
| 닫기 | 불가. **규제 고지는 사용자가 끌 수 없다** |

### 11.9 MetricValue / RateMetricValue / GapValue

이 세 컴포넌트가 §9의 표기 규칙을 강제한다.

**MetricValue**

| prop | 필수 | 설명 |
| --- | --- | --- |
| `value` | Y | 문자열 수치 |
| `unit` | Y | `PERCENT_POINT` / `POINT` / `WON` |
| `asOfDate` | **Y** | 기준일. 생략 불가 |
| `periodMonths` | 조건부 | 사이클 성과인 경우 필수 |
| `amountEquivalent` | N | 금액 병기 |
| `size` | N | `lg`/`md`/`sm` |
| `showSign` | N | 기본 true |

**RateMetricValue**

| prop | 필수 | 설명 |
| --- | --- | --- |
| `metric` | Y | API의 `RateMetric` 객체 그대로 |
| `layout` | N | `inline` / `stacked` |

`metric.is_displayable === false`이면 수치 대신 `insufficient_reason`에 대응하는 문구를 보여준다. **컴포넌트가 자체 임계값을 갖지 않는다** (API 명세 §1-5).

**GapValue**

| prop | 필수 | 설명 |
| --- | --- | --- |
| `gap` | Y | API `gaps[]` 항목 |

### 13.2 PerformanceChart

§14에서 상세히 다룬다.

### 13.3 ConditionSentence

PRD 5.3의 두 칸 구조를 그대로 시각화한다.

```
[ 목표가 대비 15% 하락 ]  하면 →  [ 전량 판다 ]
        조건 칸                    그때 할 일 칸
```

| prop | 설명 |
| --- | --- |
| `condition` | API `ConditionObject` |
| `mode` | `display` / `edit` |
| `emphasis` | `none` / `triggered` |

**두 칸의 시각적 무게가 같아야 한다.** 대응 칸을 강조하면 "그때 할 일"이 결론처럼 보이고, 조건 칸을 강조하면 "왜 파는가"가 흐려진다. 두 칸 모두 `--color-bg-surface-sunken` 배경에 동일 크기로 배치하고, 사이의 화살표만 `--color-text-tertiary`로 둔다.

`emphasis="triggered"`일 때 좌측에 4px 강조 바를 추가한다. 색은 `--color-status-warning`이며 손익 색을 쓰지 않는다 — 조건 도달은 좋은 일도 나쁜 일도 아니다.

### 13.4 ConditionActionPicker

'전량 판다 / 절반 판다 / 그대로 둔다' 3택.

| 규칙 | 내용 |
| --- | --- |
| 형태 | ChipGroup `choice` 또는 세로 RadioGroup |
| 기본 선택 | **없음** |
| 순서 | 고정 (전량 → 절반 → 그대로). 사용 빈도에 따라 재정렬하지 않는다 |
| 시각 무게 | 3개 동일. 아이콘·색·크기 차이 없음 |
| 미선택 제출 | 차단하고 필드 오류 표시 |

### 13.5 RecallCard

PRD 17.1이 허용하는 "당신이 예전에 이렇게 적었습니다" 형식의 표준 표현.

| prop | 설명 |
| --- | --- |
| `recall` | API `RecallBlock` |
| `variant` | `inline`(폼 안) / `standalone`(목록) |

**구성**: 인용 아이콘 + 작성일 캡션(`3월 12일에 이렇게 정하셨습니다`) + 원문(`body-1`, 인용 스타일) + 맥락 정보 + 이동 링크.

**시각 처리**: 좌측 3px 세로선 + `--color-accent-subtle` 배경. 사용자의 과거 발화임이 형태로 구분되어야 하며, 서비스의 말과 섞이면 PRD 17.1의 두 형식 구분이 무너진다.

### 13.6 DeviationPairRow / DeviationRow

항목별 내역은 **대칭 쌍**과 **단독 항목** 두 종류이며, 서버가 `render_group`으로 구분해 내려보낸다 (API 명세 §13.4).

| 컴포넌트 | 대상 | prop |
| --- | --- | --- |
| `DeviationPairRow` | `render_group="PAIR"` | `item`, `counterpart` (**둘 다 필수**) |
| `DeviationRow` | `render_group="SINGLE"` | `item` |

`DeviationPairRow`에 `counterpart`가 없으면 렌더링하지 않고 개발 환경에서 오류를 던진다. PRD 7.9가 요구하는 양방향 대칭을 컴포넌트 계약으로 보장하는 장치다.

**대칭 쌍은 현재 하나뿐이다**: '판다고 해놓고 안 팔았다' ↔ '보유한다고 해놓고 팔았다'. 나머지 세 항목(조건에 닿기 전에 팔았다, 계획에 없던 추가 매수, 갑자기 산 것)은 대응하는 반대 행동이 존재하지 않으므로 단독 표시한다. **없는 반대말을 억지로 만들면 존재하지 않는 행동 유형을 세게 된다.**

| 시각 처리 | 내용 |
| --- | --- |
| PairRow | 2열 그리드, 동일 폭·동일 색. 건수가 많은 쪽을 크게 하지 않는다. **좁은 화면에서도 2열 유지** |
| SingleRow | 1열 전폭. PairRow와 같은 색·타이포 |
| 배치 순서 | PairRow를 먼저, SingleRow를 뒤에. 값 크기로 재정렬하지 않는다 |
| 기준 미달 | 3건 미만은 수치를 회색으로 두고 "아직 판단하기 이릅니다" 캡션 |

### 13.7 JournalStampCalendar

| prop | 설명 |
| --- | --- |
| `stamps` | 날짜별 작성 여부 |
| `month` | 표시 월 |
| `streak` | 연속일 정보 |

**규칙**: 작성한 날에 스탬프 아이콘, 안 쓴 날은 **빈 칸**(회색 X나 경고색을 쓰지 않는다). 연속일은 상단에 숫자로만 표시하고, 끊긴 사실을 시각적으로 표시하지 않는다 (PRD 10.5).

### 13.8 PrincipleCard

| prop | 설명 |
| --- | --- |
| `principle` | |
| `variant` | `list` / `recall`(화면 중 등장) / `scorecard` |

`recall` 변형은 RecallCard와 동일한 시각 언어를 쓴다 — 수칙은 사용자가 과거에 정한 것이므로 서비스의 권유가 아니라 과거 발화다 (PRD 11.5).

보유 종목·종목 풀 목록의 시세 행.

## 14. 차트 규격

### 14.1 라이브러리 선정

| 항목 | 결정 |
| --- | --- |
| 라이브러리 | Recharts |
| 근거 | React 선언형 API, 번들 크기 중간, SVG 기반으로 접근성 처리 용이. 이 제품의 차트는 선 그래프와 막대 두 종류뿐이므로 D3 직접 사용은 과잉이다 |
| 대안 검토 | Chart.js(캔버스라 접근성 처리 어려움), 자체 SVG(유지보수 비용) |

### 14.2 성과 곡선 (4계좌 비교)

| 항목 | 규격 |
| --- | --- |
| 타입 | 다중 선 그래프 |
| 계좌별 색·선 스타일 | §3.5 표 준수 |
| Y축 | 수익률(%). 0선을 `--color-border-strong`으로 강조 |
| X축 | 날짜. 모바일에서는 시작·조정일·현재만 라벨 |
| 이벤트 마커 | 정기 조정일(세로 점선), 비상 선언(아이콘 마커), 조건 도달(작은 점), 결산일(세로 실선). **데이터 출처는 성과 응답의 `events` 배열** (API 명세 §13.3). 별도 조회로 조합하지 않는다 |
| 툴팁 | 탭 시 해당 날짜의 4계좌 값 전부 표시 + 그날 날짜 |
| 범례 | 차트 하단. 탭으로 개별 계좌 표시/숨김 |
| 빈 데이터 | 시작 직후에는 곡선 대신 "아직 곡선을 그리기에 이릅니다" |
| 애니메이션 | 최초 렌더 시 좌→우 그리기 400ms. 값 갱신 시에는 없음 |

**툴팁에 4계좌를 모두 표시하는 것이 중요하다.** 하나만 보여주면 비교라는 기능의 목적이 사라진다.

### 14.3 종목 시세 차트

| 항목 | 규격 |
| --- | --- |
| 타입 | 종가 기반 선 그래프 (캔들 아님) |
| 근거 | 일별 종가만 판정에 쓰므로(PRD 7.11-3) 캔들은 사용자에게 장중 정보가 있다는 오해를 준다 |
| 오버레이 | 매수·매도 지점 마커, 조건 임계가 수평선 |
| 기간 선택 | 1M / 3M / 6M / 사이클 전체 |

### 14.4 항목별 내역 차트

| 항목 | 규격 |
| --- | --- |
| 타입 | 수평 막대. 좌우 대칭 배치 |
| 색 | 짝을 이루는 두 항목에 **동일 색**을 쓴다. 방향만 다르게 |
| 정렬 | 카테고리 고정 순서. 값 크기로 재정렬하지 않는다 |

값 크기로 정렬하면 가장 큰 항목이 항상 위에 오고, 그것이 곧 "당신의 문제는 이것"이라는 서비스의 판단이 된다.

| 항목 | 규칙 |

## 15. 폼과 입력 마찰 설계

PRD 4.3의 "30초 규칙"과 "입력 마찰 최소화"를 구현하는 규칙이다.

### 15.1 입력 형태 우선순위

| 순위 | 형태 | 사용 조건 |
| --- | --- | --- |
| 1 | Chip 단일 선택 | 선택지 2~8개 (기분, 대응, 태그) |
| 2 | SegmentedControl | 선택지 2~4개, 상호 배타 |
| 3 | Slider / 5단계 Chip | 정도 표현 (확신도) |
| 4 | 숫자 입력 | 수치가 필요할 때 |
| 5 | 자유 텍스트 | 위로 표현 불가능할 때만 |

### 15.2 필수·선택 표시

| 규칙 | 내용 |
| --- | --- |
| 필수 표시 | 라벨 뒤 `*` 대신 **`(필수)` 텍스트**. 별표는 인지 부담이 있다 |
| 선택 표시 | `(선택)` 명시. **표시하지 않으면 사용자는 전부 필수로 인식한다** |
| 필수 항목 총량 | 화면당 1~2개를 넘지 않는다 (PRD 4.3의 필수 입력 총량 표 준수) |
| 나중에 채우기 | 선택 항목이 있는 폼에는 "나중에 채울 수 있습니다" 캡션 |

### 15.3 저장 동작

| 상황 | 동작 |
| --- | --- |
| 일지 | 항목 단위 자동 저장(디바운스 1초). 명시적 저장 버튼도 함께 제공 |
| 매매 기입 | 명시적 제출만. 자동 저장하지 않는다(금융 데이터) |
| 가설 기록 | 매매 기입과 같은 제출에 포함 |
| 회고 | 항목별 자동 저장. 중간 이탈 후 재진입 가능 |
| 시트 닫기 | 입력값 보존. 초기화하지 않는다 |

### 15.4 검증

| 시점 | 규칙 |
| --- | --- |
| 입력 중 | 검증하지 않는다 (타이핑 중 빨간 테두리는 마찰) |
| 포커스 이탈 | 형식 검증 |
| 제출 | 전체 검증. 첫 오류 필드로 스크롤 + 포커스 |
| 서버 오류 | `field_errors`를 필드에 매핑. 매핑 실패 시 폼 상단 배너 |

### 15.5 오류 문구

API가 내려준 `message`를 그대로 쓴다. 클라이언트가 만드는 문구는 **네트워크 오류와 클라이언트 검증 실패**뿐이며, 그 문구도 같은 톤 규칙을 따른다.

## 16. 피드백 — 로딩·빈 상태·오류

### 16.1 로딩

| 상황 | 처리 |
| --- | --- |
| 첫 진입 | Skeleton. 스피너 전체 화면 금지 |
| 페이지 전환 | 상단 진행 바(2px) |
| 버튼 액션 | 버튼 내 스피너 + 비활성 |
| 백그라운드 갱신 | 표시하지 않음. 기존 데이터 유지 |
| 재계산 대기 (`recompute_pending`) | 계좌 영역에 "정정한 내용을 반영하는 중입니다" 인라인 배너 + 기존 값 흐리게 |

### 16.2 빈 상태 카탈로그

| 화면 | 문구 방향 |
| --- | --- |
| 매매 내역 없음 | "아직 기입한 매매가 없습니다." |
| 일지 없음 | "이 달에는 아직 기록이 없습니다." |
| 깨달은 것 없음 | "별표를 눌러 표시한 문장이 여기 모입니다." |
| 조건 도달 없음 | "아직 되돌아볼 조건에 닿은 종목이 없습니다." |
| 수칙 없음 (첫 사이클) | "첫 결산 때 이번 사이클의 수칙을 만들게 됩니다." |
| 배지 없음 | "기록이 쌓이면 배지가 나타납니다." |
| 리포트 없음 | "결산일에 올해의 투자 레슨을 받게 됩니다." |
| 사이클 공백기 | "올해 다이어리는 덮었고, 내년 것은 아직 나오지 않았습니다." (PRD 13.1) |
| 실적 일정 없음 | "예정된 실적 발표 일정이 없습니다." |
| 공시 없음 | "이 기간에 접수된 공시가 없습니다." |

### 16.3 오류 상태

| 유형 | 처리 |
| --- | --- |
| 네트워크 | 전체 화면 ErrorState + 재시도 버튼 |
| 401 | 자동 갱신 시도 → 실패 시 로그인 화면 |
| 403/404 | 전체 화면 ErrorState + 홈으로 |
| 409/422 (도메인) | 인라인 또는 토스트. `message` 그대로 |
| 500 | ErrorState + `request_id` 표시 + 재시도 |
| 503 (배치 중) | "오늘의 시세를 정리하는 중입니다" + 자동 재시도 안내 |

## 17. 마이크로카피 규칙

PRD 4.1과 17.1을 화면 문구 수준의 규칙으로 정리한다. **이 절은 디자이너와 개발자 모두의 검수 기준이다.**

### 17.1 두 가지 허용 형식

| 형식 | 표지 | 시각 처리 |
| --- | --- | --- |

## 18. 접근성

목표 수준: **WCAG 2.1 AA**.

### 18.1 색 대비

| 대상 | 최소 대비 |
| --- | --- |
| 본문 텍스트 | 4.5:1 |
| 큰 텍스트(≥18.66px bold, ≥24px) | 3:1 |
| UI 컴포넌트 경계·아이콘 | 3:1 |
| 차트 선 | 배경 대비 3:1, 인접 선 간 구분 가능 |

`--color-text-tertiary`(기준일 캡션)도 4.5:1을 만족해야 한다. 기준일은 법적·정직성 요구사항이므로 흐리게 처리해서는 안 된다.

### 18.2 색 이외의 단서

| 대상 | 추가 단서 |
| --- | --- |
| 손익 | 부호(`+`/`−`) + 방향 아이콘 |
| 계좌 구분 | 선 스타일(실선/파선/점선) + 범례 |
| 선택 상태 | 체크 아이콘 |
| 오류 | 아이콘 + 텍스트 |
| 조건 도달 | 아이콘 + 라벨 |

### 18.3 키보드

| 항목 | 규칙 |
| --- | --- |
| 포커스 순서 | DOM 순서와 시각 순서 일치 |
| 포커스 표시 | `--color-border-focus` 2px 외곽선 + 2px 오프셋. `outline: none` 단독 사용 금지 |
| 모달·시트 | 포커스 트랩, Esc로 닫기 |
| 건너뛰기 링크 | 본문 바로가기 제공 |
| 커스텀 컴포넌트 | Chip·SegmentedControl은 화살표 키 이동 지원 |

### 18.4 스크린 리더

| 항목 | 규칙 |
| --- | --- |
| 랜드마크 | `header`, `nav`, `main`, `footer` 사용 |
| 아이콘 버튼 | `aria-label` 필수 |
| 동적 갱신 | 토스트·오류는 `aria-live="polite"`, 치명 오류는 `assertive` |
| 차트 | 대체 표 제공 (`sr-only`) |
| 수치 | `aria-label`에 단위와 기준일 포함 (`"수익률 플러스 3.1퍼센트포인트, 8월 3일 종가 기준"`) |
| 비율 | 분모를 포함해 읽히도록 (`"7회 중 4회"`) |

### 18.5 기타

| 항목 | 규칙 |
| --- | --- |
| 확대 | 200% 확대에서 가로 스크롤 없이 동작 |
| 폰트 크기 | 사용자 시스템 설정 존중 (`rem` 단위 사용) |
| 모션 | `prefers-reduced-motion` 대응 |
| 다크 모드 | `prefers-color-scheme` + 사용자 명시 설정 우선 |

## 19. Tailwind 구성 방침

### 19.1 설정 구조

| 파일 | 역할 |
| --- | --- |
| `tailwind.config.ts` | theme 확장, 플러그인, content 경로 |
| `src/shared/styles/tokens.css` | CSS 변수 정의 (`:root`, `[data-theme="dark"]`) |
| `src/shared/styles/base.css` | `@tailwind base` + 리셋 보강 |
| `src/shared/styles/components.css` | `@layer components`의 최소 유틸 |
| `src/shared/styles/index.css` | 위 파일들의 진입점 |

### 19.2 theme 확장 원칙

| 항목 | 방침 |
| --- | --- |
| 색상 | 기본 팔레트를 **비우고** 시맨틱 토큰만 노출한다. `text-gray-500` 같은 클래스가 코드에 등장하지 못하게 한다 |
| 간격 | 기본 스케일 유지 + 시맨틱 별칭 추가 |
| 폰트 크기 | 기본 스케일을 §4.2 타입 스케일로 **교체**한다 (`text-body-1` 형태) |
| 반경·그림자 | 기본 교체 |
| 브레이크포인트 | 기본 유지 |

> 기본 팔레트를 비우는 것이 이 시스템의 핵심 강제 장치다. Tailwind의 편의성은 임의 색 사용의 편의성이기도 하며, 색이 흩어지면 손익 색 반전 설정과 다크 모드가 동시에 깨진다.

### 19.3 클래스 작성 규칙

| 규칙 | 내용 |
| --- | --- |
| 조건부 클래스 | `clsx` + `tailwind-merge` 조합 (`cn` 유틸) |
| 변형 관리 | `class-variance-authority`(CVA)로 컴포넌트 variant 정의 |
| 임의 값 | `[...]` 임의 값 사용 금지. 필요하면 토큰을 추가한다 |
| `@apply` | 컴포넌트 파일에서 사용하지 않는다. 전역 리셋에서만 제한적으로 |
| 정렬 | `prettier-plugin-tailwindcss`로 클래스 순서 자동 정렬 |

### 19.4 다크 모드

`darkMode: ['class', '[data-theme="dark"]']`. 시스템 설정 감지 후 `data-theme` 속성을 루트에 설정하며, 사용자가 명시 선택하면 그 값이 우선한다. 컴포넌트에는 `dark:` 변형을 거의 쓰지 않는다 — 색은 전부 CSS 변수이므로 값만 바뀐다.

## 21. 품질 체크리스트

새 화면·컴포넌트 구현 시 아래를 확인한다.

**표기**
- [ ] 모든 성과 수치에 기준일이 붙어 있는가
- [ ] 사이클 성과에 기간(○개월)이 붙어 있는가
- [ ] 모든 비율이 분모와 함께 표시되는가
- [ ] 두 준수율이 별개 이름으로 분리되어 있는가

- [ ] `render_group="PAIR"` 항목이 짝과 함께 2열로 렌더링되는가
- [ ] 단독 항목에 인위적인 반대말을 만들지 않았는가

- [ ] 기본 선택값이 없는가

- [ ] 금지 표현 목록에 걸리는 문구가 없는가
- [ ] 용어 사전을 벗어난 단어가 없는가
- [ ] 축하·훈계·권유 문구가 없는가
- [ ] 빈 상태 문구가 재촉하지 않는가

- [ ] 손익이 색 이외의 단서를 갖는가
- [ ] 키보드로 전체 조작이 가능한가
- [ ] 아이콘 버튼에 레이블이 있는가
- [ ] 차트에 대체 표가 있는가

- [ ] 375px에서 가로 스크롤이 없는가
- [ ] 터치 타깃이 44px 이상인가
- [ ] 200% 확대에서 동작하는가
